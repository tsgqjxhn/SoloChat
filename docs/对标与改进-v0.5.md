## 结论摘要

1. **四个目标不是四个功能，而是四种「资产」**：Chat 的资产是「好看的答案」，Work 的资产是「可交付的产物」，Agent 的资产是「可回退的代码改动」，新模式的资产是「记得住的关系与经验」。混在一起做，每个都会做浅。
2. **当前最大的瓶颈不是想法，是体积**：`index.html` 1,023,303 B / 上限 1,048,576 B，只剩 **25,273 B（2.4%）**。四模式改造粗估需要 **+113～171 KB**，不先解决上限，任何一条都做不完。
3. **Chat 缺的不是 Markdown，是「图片流」**：现在流式期刻意不出图（`MD.render(..., {noMedia:true})`，index.html:7299），也没有任何生图工具。对标 ChatGPT 要补的是「生图 → 渐进出图 → 图入库 → 可编辑/重生成」整条链。
4. **Work 缺的不是爬虫，是「看得见页面」**：`browser` 只会开窗（宿主 `webview` 只有 show/reload/hide），模型拿不到 DOM，登录页/JS 站点等于黑盒。Steam 合集这类页面必须靠「读页面 + 点击/滚动 + 截图」闭环。
5. **Agent 缺的不是提示词，是「检索 + 诊断 + 回退」**：没有 grep/glob，`patch` 只在 Work，快照存在 localStorage（整文件内容），没有回合级 rewind。这三样决定它像不像 Claude Code/OpenCode。
6. **新模式定名 `Soul`**：与 SoloChat 品牌呼应，语义直指「人格与记忆的连续性」。它的核心不是更多工具，而是**文件优先的长期记忆 + 可审阅的成长 + 克制的主动性**。P12 升 `0.5.0`（已获授权）。

## 2. Chat：对标 ChatGPT 的「富文本 + 图片流」

### 2.1 对标事实（2026-11）

- **渲染**：GFM 全量（表格对齐、任务列表、脚注、嵌套引用）、代码块语法高亮 + 复制/换行、LaTeX 真排版、引用角标与来源页脚、长内容折叠。
- **图片**：文生图直接在回复里出图；**生成过程渐进出图**（OpenAI `partial_images` 0–3，Responses `image_generation` 工具与 Images API 都支持流式部分图）；支持参考图编辑、多张变体、下载、重生成。
- **交互**：编辑用户消息后重发、回答多版本、临时会话、画布侧栏、记忆。

### 2.2 现状与差距

| 能力 | SoloChat 现状 | 差距 |
|---|---|---|
| 表格 | 支持（index.html:5405），**无对齐** | 补 `:--:` 对齐 |
| 任务列表 / 脚注 / 定义列表 | 无 | 补 |
| 代码高亮 | 无（只有工具条：复制/下载/换行/行号） | 补零依赖轻量高亮 |
| LaTeX | 文本级近似（`\frac`→`a⁄b`，5196），不是排版 | 补常用矩阵/积分/求和/多行，或引入自研盒模型 |
| 图片输入 | 支持四协议 vision，压缩到 ≤512 KB（1275） | 基本够用 |
| 回答内嵌图/视频 | 支持 https 直链（CSP 允许 blob/https） | 够用 |
| **生图** | **完全没有** | 新增 `IMG` + `image` 工具 |
| **图片流** | **流式期禁媒体**（7299），收尾才出图 | 改为渐进出图 |
| 画布 | Chat 右侧栏禁用 | Chat 专属「文档画布」 |
| 消息编辑 | 有（`editMsg`，12113） | 补「编辑后从此处重发」 |
| 引用 | 消息页脚来源（v0.3.32） | 补正文角标 `[1]` 联动 |

### 2.3 设计

**C1 富文本补全（预估 +6～9 KB）**
- `MD.render` 增加：任务列表（`- [ ]`/`- [x]`，可点击切换仅本地态）、脚注（`[^1]` + 末尾定义）、表格列对齐、定义列表（`term\n: def`）、嵌套引用层级、`<details>` 之外的「长表格横向滚动」。
- 代码高亮：自研 12 种语言（js/ts/py/html/css/json/bash/sql/go/rs/java/cs/md）的**关键字+字符串+注释+数字**四类着色，约 3 KB；不做 AST。样式走 CSS 变量，暗色自动适配。
- 公式：保留现有 fallback，新增 `\begin{matrix}`/`\sum_{}^{}`/`\int_{}^{}`/`\lim`/`\overline` 的盒式渲染（上下标定位用 inline-block + vertical-align，不引 KaTeX）。
- 验收：一条消息覆盖全部语法，截图人工核对 + 控制台 0 error。

**C2 图片生成与「图片流」（预估 +14～20 KB）**
- 新模块 `IMG`：
  - `generate({prompt, size, n, refs[]})` → 依据 `cfg.imageProvider`（默认复用当前连接，若协议/模型不支持则读独立配置）调用：
    - OpenAI `POST /v1/images/generations`（`response_format:b64_json`）
    - OpenAI Responses `image_generation` 工具（支持 `partial_images`）
    - 兼容端点（自定义 path/字段，走 `quirks`）
  - `edit({image, mask?, prompt})` → `/v1/images/edits`（先用 prompt 编辑 + 参考图，不做蒙版画笔）。
  - 事件：`onPartial(b64, index)`、`onFinal(b64)`、`onError`。
- 渲染：消息内 `figure.img-gen`，先出低清/部分帧（`blob:` URL，CSP 已允许），带扫描线/骨架；完成后替换为最终图；底部工具条：下载、复制 prompt、重生成、编辑、加入参考图。
- 落库：图片存 `attachments`（blob/base64），消息只存 `imgId`，避免消息表膨胀；导出时按需内联。
- 流式协议：Responses 的 `response.image_generation_call.partial_image` 事件（b64 + partial_index）；若 provider 不支持，退化为「先占位卡 → 完成出图」。
- 新工具 `image`（Chat 也可用，这是 Chat 第一次有工具）：`image <prompt>` → 生成并内嵌；`image.edit` 走参数行。
- 验收：真 provider 生成 1 张 1024²，至少看到 2 帧渐进；刷新后图仍在；失败有错误卡；无 provider 时提示配置而不是静默。

**C3 流式媒体（预估 +2 KB）**
- 7299 的 `noMedia` 改成三态：`stream`（允许已完成的 blob/短 https 图，懒加载）、`final`（全量）。
- 未闭合代码围栏不闪：渲染前做「围栏配对检查」，未闭合时按纯文本转义，闭合后重渲染该块（局部替换，不整段重排）。
- 验收：生成中含图片链接与未闭合围栏，滚动不跳、图不重复请求。

**C4 引用体系（预估 +3 KB）**
- 正文 `[1]` 角标 → hover 卡片（标题/域名/摘要）→ 点击滚到页脚来源或打开外链。
- 来源页脚增加 favicon（用 `https://域名/favicon.ico`，失败回退首字母圆点）。
- 验收：搜索问答后角标与来源一一对应。

**C5 Chat 文档画布（预估 +5～8 KB）**
- Chat 下右侧栏从「禁用」改为「画布」：当前会话的长文/代码产物，可编辑、保存、版本回退（复用快照数据结构，键 `sid|canvas|docId`）。
- 触发：回答里的「在画布打开」按钮；或 `/canvas`。
- 验收：编辑保存后刷新仍在；回退到上一版成功；不影响 Work/Agent 面板。

**C6 消息级操作（预估 +2 KB）**
- 「编辑并从此处重发」：截断后续消息（保留可恢复副本）、重建上下文。
- 图片消息：重生成 / 变体切换（复用多版本机制）。

### 2.4 验收用例（Chat）

1. 富文本全家桶一条消息渲染正确，暗色/亮色都正常。
2. 生图：partial ≥2 帧；最终图入库；下载/重生成可用。
3. 流式：未闭合围栏不闪；图片渐进出现。
4. 附件：3 图 + 1 PDF，模型能引用图内容且读到 PDF 文本。
5. 画布：编辑→刷新→回退。
6. 引用角标与来源联动。

### 2.5 裁剪

- 不做语音、不做实时视频、不做蒙版画笔、不做多图拼贴编辑器。
- 公式不做完整 TeX（矩阵之外的长公式允许横向滚动）。

## 3. Work：对标 Arena Agent Mode 的「脚本 / 爬虫 / 看页面」

### 3.1 对标事实

Arena Agent Mode（2026-11）：
- 自主建计划，内置 **web search / image generation / coding / 文件上传 / bash 沙箱**，多步任务一口气做完。
- 右侧 **Workspace** 面板；未连 GitHub 可 **下载 zip**；连了 GitHub 则提交到工作分支并 **开 PR**，有 **Diff** 页。
- **Connectors**：Gmail、Google Drive、Calendar、Linear、Vercel、Supabase 等。
- 会 **反问澄清**。
- Agent 排行榜五个信号：**confirmed success / praise vs complaint / steerability / bash recovery / tool hallucination** —— 这五项可以直接拿来当我们的验收维度。

### 3.2 现状与差距

| 能力 | 现状 | 差距 |
|---|---|---|
| 计划 | 提示词要求「阶段顺序」，无 UI | 计划卡 + 步骤状态 |
| 脚本 | 只有 `run`（JS/HTML/CSS），Python 仅 Agent | Work 需要 Python/Node 真执行 |
| 沙箱 | 内存 VFS，不落盘 | 临时目录 + 可清理 |
| 看页面 | `browser` 开窗、`shot` 截图；**模型读不到 DOM** | 读文本/可访问性树 + 点击/输入/滚动 |

| 中途 steer | 只能等本轮结束 | 运行中插话改方向 |
| 生图 | 无 | 与 Chat 共用 `IMG` |

### 3.3 设计

**W1 浏览器「读 / 动 / 证」三件套（预估 +10～16 KB，宿主 +300 行）**
- 宿主新增 `webview` op：
  - `read`：`ExecuteScriptAsync` 注入只读脚本，回 `{title,url,text,links[],forms[]}`；文本按可读性裁剪（正文优先，去导航/广告），上限 20 KB。
  - `act`：`click(selector|text)`、`type(selector,text)`、`scroll(dy)`、`wait(ms|selector)`、`back/forward`；每步回「动作结果 + 新 URL + 是否出现新内容」。
  - `shot`：已有 `CapturePreviewAsync`，补「按元素裁剪」可选。
  - `downloads`：页面触发的下载落到会话目录并回路径。
- 页面侧工具：`browser-read`、`browser-act`、`browser-wait`；`browser` 保留为「打开」。
- 视觉回注：`shot` 结果同时作为 `image_url` 内容段回注给多模态模型（当前只把 data URL 贴进助手消息给用户看，index.html:17015-17018，模型看不到）。
- 安全：独立 **agent profile**（`%LOCALAPPDATA%\OpenPage\webagent`）与「用户登录态 profile」二选一；银行/邮箱/支付域名默认阻断；所有 act 写审计日志。
- 验收：Steam 合集页 `read` 能拿到全部条目名；点「加载更多」两次后条目数增加；截图非空白。

**W2 临时沙箱（预估 +8～12 KB，宿主 +150 行）**
- 目录：`%LOCALAPPDATA%\OpenPage\work\<sid>\`，会话结束可选保留/清理；所有路径限制在目录内。
- 能力：`sh`（受限：node/python/git/curl 白名单，无管道重定向解析风险）、`python`（复用 python-3.11 运行时）、`node`（系统 node）。
- 与 Agent 的区别：Work 沙箱**默认每次执行前不弹确认**（因为是临时目录），但**禁止访问工作区外路径**、禁网（可选开关）。
- 验收：上传 CSV → Python 清洗 → 输出统计表 + 结果文件；脚本失败能读 stderr。

**W3 结构化提取（预估 +6～10 KB）**
- 新工具 `extract`：`extract <url|当前页> --items "<selector>" --fields "name:.title,price:.price,discount:.disc"` → JSON/CSV 落工作区。
- 支持：CSS 选择器（用宿主注入的 `querySelectorAll`，不用第三方库）、分页（`--next` 选择器 + 最多 N 页）、去重键、限速（默认 1 req/s）、失败条目清单。
- 对 JS 站点：先 `browser-read` 渲染后的 DOM，再 `extract`（两者共用同一套选择器执行器）。
- 验收：Steam 合集 → CSV，字段齐全、条数与页面一致、失败项有原因。

**W4 计划卡 + 中途 steer（预估 +7～10 KB）**
- 数据结构：`tasks` 扩为 `plan`（`sid`, `steps:[{id,title,status,evidence}]`），消息流顶部渲染可折叠计划卡。
- 模型协议：```plan 步骤列表``` → 执行中每步 ```plan-step done|failed <id> <证据>```。
- steer：生成中用户发消息 → 不打断当前工具链，插入「用户修正」到下一轮上下文，并在计划卡标注「已按你的修正调整」。
- 验收：三步任务中途改需求，后续步骤随之变化，计划卡状态正确。

**W5 交付（预估 +3 KB）**
- 工作区：单文件下载、全部打包 zip（已有 `/zip`）、「用本地 HTTP 打开」（临时起服务，宿主打开浏览器）。
- 不做云端部署（Vercel/CF 连接器后置）。

**W6 连接器（MCP 打通，预估 +8～12 KB）**
- `tools/list` 拉清单 → 转成 `EXT` 工具（声明式，`mcp:<server>:<tool>`）→ `tools/call` 执行 → 结果回注。
- 首批只做 1 个示范（GitHub：列 issue / 读 PR diff），证明链路。
- 验收：登记一个 MCP 服务器，工具出现在选择器里，调用有结果。

**W7 失败恢复（预估 +3 KB）**
- 统一 `recover` 策略：工具失败 → 原文回注（含 stderr 前 2 KB）→ 模型修 → 重跑，最多 3 次；每次记录到证据条；3 次后停并给「卡在哪」。
- 对应 Arena 的 **bash recovery** 指标。

### 3.4 验收用例（Work）

1. **Steam 合集（主用例）**：给一个合集/捆绑包 URL，要求「全部游戏名 + 原价 + 现价 + 折扣，存 CSV，报告条数」。验收：条数与页面一致（±0）、CSV 可打开、失败项列出。
2. **脚本**：CSV 清洗 + 统计，Python 在临时沙箱跑，输出表 + 文件。
3. **网页应用**：生成 3 文件站点 → `/check` 无缺失 → 预览截图非空白 → 改一处 → 再预览。
4. **断点恢复**：中途断网/工具失败，最终产物完整，证据条显示重试次数。
5. **steer**：执行中插入「只要免费游戏」，计划随之改变。
6. **交付**：zip 内容与工作区一致；单文件下载可用。

### 3.5 风险

- Steam 有地区/年龄/登录墙与反爬；验收以「能读、能提取、失败有解释」为准，不承诺 100% 站点。
- 沙箱不是 OS 级安全边界（无容器），文档与 UI 必须写明「临时目录 + 白名单，不是沙箱逃逸防护」。
- 浏览器自动化会触发验证码；需要「人工接管」按钮（用户手动点完，agent 继续）。

### 4.3 设计

**A1 检索三件套（预估 +6～9 KB）**
- `fs-grep`：`pattern`（正则）、`--glob`、`-i`、`-A/-B` 上下文、`--max` 条数、返回 `path:line: text`；实现走宿主新 op `grep`（ripgrep 若存在则用，否则 JS 遍历 + 忽略 `.git/node_modules/dist`）。
- `fs-glob`：按名找文件（`**/*.ts`），返回路径 + 大小 + mtime。
- `fs-stat`：单文件元信息（大小/行数/编码/是否二进制）。
- 验收：在 SoloChat 仓库问「SSE 解析在哪」，命中 `createParserFor`/`parseNonStream` 行号，不整读文件。

**A2 编辑升级（预估 +5～8 KB）**
- 把 `patch` 加进 Agent（unified diff + 唯一上下文校验）。
- 写入前：`fs-diff` 预览（旧/新对照，红绿行），UI 卡片「应用 / 取消 / 全部应用」。
- `acceptEdits`：`permMode=auto` 时工作区内自动应用，工作区外仍确认。
- 验收：改 3 个文件，diff 卡片逐条可应用；取消后文件不变。

**A3 计划/待办（预估 +5 KB）**
- `todo` 工具 + 会话级列表；模型每完成一步更新；UI 顶栏显示 `2/5`。
- `/todos` 查看，`/todos clear` 清空。
- 验收：5 步任务全程状态正确，刷新后仍在。

**A4 诊断桥（预估 +6～10 KB）**
- `diag` 工具：按项目类型自动选命令——
  - Node/TS：`npx tsc --noEmit`（有 tsconfig）、`node --check`（单文件）
  - Python：`python -m py_compile`、`pytest -q`
  - .NET：`dotnet build`
  - Go：`go vet ./...`
  - 通用：`tools/verify.mjs`（本项目）
- 输出结构化：`file:line:col severity message`，去重、限 50 条；失败原样回注。
- 自动触发：每次 `fs-write/fs-edit/patch` 后，若 `cfg.autoDiag` 开且项目有诊断器，跑一次（限时 60s）。
- 验收：故意写错一个 JS 语法，模型读诊断后修复，`verify` 通过。

**A5 项目规则（预估 +3 KB）**
- 读取顺序：`<workspace>/AGENTS.md` → `<workspace>/.solochat/rules.md` → 全局 `%USERPROFILE%\.solochat\AGENTS.md`；合并注入（上限 4 KB，超出截断并提示）。
- `/rules` 查看当前生效规则与来源。
- 验收：写一条「不要改 host/Program.cs」，下一轮模型遵守并说明。

**A6 检查点/回退（预估 +8～12 KB）**
- 快照从 localStorage 迁到 IndexedDB `checkpoints`（`sid|ws|path`，最多 5 版，单版上限 512 KB，超出只存 diff）。
- 回合检查点：每轮开始记录「本轮会写哪些文件」的旧内容；`/rewind` 回到上一轮（文件 + 会话二选一，对齐 Claude Code）。
- UI：消息上的「撤销这轮」；设置页「检查点」列表可删。
- 验收：一轮改 4 文件 → `/rewind` → 4 文件全恢复；另一会话同名文件不受影响。

**A7 命令与安全（预估 +3 KB）**
- 超时默认 120s，超时杀进程树（Windows `taskkill /T /F`）。
- 危险命令二次确认（`rm -rf`、`format`、`del /s`、`git reset --hard`、`git clean -fd`）——即使 auto。
- 审计日志补「退出码 + 耗时 + 截断字节」。
- 验收：长命令超时被终止，UI 有提示，审计有记录。

**A8 上下文工程（预估 +5～8 KB）**
- 仓库地图：扫描工作区（遵守 `.gitignore` + 内置忽略），生成「目录 → 文件数 → 关键文件」摘要（≤2 KB），随系统提示注入。
- 文件摘要缓存：`fs-read` 过的文件记 `{path, mtime, hash, summary}`，未变则不重复读全文（省 token）。
- 验收：大仓库首轮不爆 token；重复读同文件命中缓存。

**A9 子智能体隔离（预估 +4 KB）**
- 写类子智能体（build/fix）在 `_sub/<role>-<n>/` 副本工作，母体合并；只读类（explore/verify）共享。
- 验收：两个 build 并行改同名文件不互相覆盖，母体合并时冲突可见。

**A10 自定义命令（预估 +3 KB）**
- `<workspace>/.solochat/commands/*.md`：文件名即命令，正文为提示词，`$ARG` 替换；`/` 面板可搜到。
- 验收：新建 `review.md`，`/review` 生效。

### 4.4 验收用例（Agent）

1. 「找出所有处理 SSE 解析的地方」→ 用 grep，给行号，不整读。
2. 「修一个真实缺陷」→ 计划 → 读 → patch → diag → 修复 → 交付；`verify` 6/6，`git diff` 只含预期文件。
3. `/rewind` 回上一轮，文件恢复、会话保留。
4. `AGENTS.md` 约定生效。
5. 诊断：故意语法错误 → 读诊断 → 修复。
6. 子智能体并行写不同文件，结果正确合并。

### 4.5 风险

- 诊断命令依赖工作区工具链，缺 node/python 时要有降级提示。
- grep 自研实现在超大仓库可能慢；优先用系统 `rg`（宿主 `cmd` 白名单加 `rg`），没有则 JS 兜底（限 5 万文件）。
- 检查点迁 IndexedDB 需要 DB v4 迁移，必须幂等 + 兼容旧 `sc.snaps`。

## 5. 第四个模式：对标 Hermes / OpenClaw 的「会成长的长期记忆体」

### 5.1 为什么不是 Agent 的超集

| | Agent | 新模式 |
|---|---|---|
| 时间尺度 | 一次任务 | 数月/数年 |
| 资产 | 代码改动 | 记忆、偏好、技能、承诺 |

| 主要风险 | 改错文件 | 记忆污染、越权、隐私泄露 |
| 默认权限 | 工作区读写 | **读默认、写确认、外发确认** |

一句话：Agent 是「手」，新模式是「记忆和习惯」。工具能力复用 Agent，但策略更保守。

### 5.2 对标事实

**Hermes（本机）**：`MEMORY.md` + `USER.md` 双文件、硬字符预算、每轮注入；技能按需加载（`skill_view`）；`session_search` 检索历史；cron 定时；delegation 隔离子智能体；MCP/connectors。

**OpenClaw（2026-11 文档）**：
- 四个记忆文件：`USER.md`（稳定偏好，独立小预算）、`MEMORY.md`（长期事实，启动加载）、`memory/YYYY-MM-DD.md`（每日笔记，按需检索）、`DREAMS.md`（巩固日记）。
- **文件即记忆**：只有写进磁盘的才被记住，无隐藏状态；`memory_search` / `memory_get` 显式检索。
- **Dreaming**：后台巩固（light/deep/REM），把日笔记蒸馏进 `MEMORY.md`，生成可审阅报告；写前留 preimage，可回滚。
- **Provenance**：来源不可信的文件会被排除出自动上下文，`doctor` 可查。
- **Skills Workshop**：agent 自己学技能，有变更历史与撤销。
- **浏览器**：独立 `openclaw` profile，agent 可开标签/读页/点击/输入/截图/PDF；另有 `user` profile 接真实登录态。
- **定时/心跳**：cron、hooks、webhooks。
- **导入**：可从 Claude Code / Codex / Hermes 导入 Markdown 记忆。

### 5.3 命名方案

| Life | 生活 | 日常陪伴感强 | 弱化工程能力，像日程助手 |

### 5.4 设计

**S1 记忆四层 + 文件优先（预估 +12～18 KB）**

| 层 | 文件 | 内容 | 注入策略 |
|---|---|---|---|
| 用户模型 | `USER.md` | 称呼（老公）、语气偏好、忌讳、作息、长期项目 | 每轮注入，独立预算 600 字 |
| 长期记忆 | `MEMORY.md` | 稳定事实、决定、约定、重要事件 | 每轮注入，预算 1,200 字 |
| 日记 | `memory/YYYY-MM-DD.md` | 当天要点、任务结果、观察 | 不自动注入，`memory_search` 检索 |
| 程序记忆 | `skills/<name>/SKILL.md` | 可复用步骤、坑、验收 | `skill` 工具按需加载 |

- 目录：`%USERPROFILE%\SoloChat\memory\`（可由用户在设置里改）；IndexedDB 存索引与元数据（hash、ts、来源、置信度），**Markdown 为真源**。
- 双写：UI 编辑 → 写文件 + 更新索引；外部改文件 → 启动/定时比对 mtime 重新索引。
- 兼容：支持导入 OpenClaw 的 `USER.md`/`MEMORY.md`（只取 Markdown，不取配置/凭据）。

**S2 写入策略（预估 +6～10 KB）**
- 显式：用户说「记住…」→ 直接写，回执「已记住（写入 MEMORY.md）」。
- 隐式候选：每轮结束抽取候选（事实/偏好/承诺/教训），四项打分：**新颖性、稳定性、可复用性、用户显著度**；≥阈值才写，否则进「待确认」列表（设置页可批量采纳/丢弃）。
- 敏感过滤：密钥/密码/银行卡/身份证/住址精确门牌 → 拒写并提示；健康/财务等敏感类默认只写「用户提到过某类话题」不写细节。
- 冲突：同一主语+谓词的新值**替换**旧条目（`supersedes` 链），不追加矛盾条目；UI 显示「已更新：旧值 → 新值」。
- 来源：`user` / `tool` / `web`（不可信，默认不进长期记忆，除非用户确认）。
- 验收：说「我周三晚上打球」→ 文件出现带日期的条目；说「改用浅色主题」→ 旧的深色偏好被替代而不是并存；说 API key → 拒写。

**S3 检索与注入（预估 +8～12 KB）**
- 词法：BM25-lite（复用现有 `toks`/`score`，加 IDF 与长度归一）；中文 bigram 已有。
- 语义（可选）：用户开「语义记忆」后，调用当前 provider 的 embedding 端点（需配置），本地存向量；默认**关**，开启时明示「记忆文本会发往 provider」。
- 混合排序：`0.55*相关 + 0.25*时间衰减 + 0.20*类型先验`（承诺/偏好 > 日记）。
- 注入：每轮取 Top-K（K≤6，总预算 1.5K tokens），附「本轮用到 3 条记忆」可点开；模型可用 `memory_search`/`memory_get` 主动查。
- 验收：新会话问「我周三晚上有什么安排」→ 命中并回答；点开能看到来源文件与时间。

**S4 巩固（Dreaming-lite，预估 +8 KB）**
- 触发：每日首次启动 + 空闲 10 分钟；或 `/dream`。
- 流程：读最近 7 天日记 → 聚类 → 提炼「稳定事实/决定/未完成承诺」→ 生成 `MEMORY.md` 候选 diff → 自动应用（可配置为「需确认」）→ 写 `DREAMS.md` 记录。
- 保留：每次改写留 preimage，可一键回滚；`/dreams` 查看历史。
- 验收：造 3 天日记 → 巩固 → `MEMORY.md` 多一条摘要，`DREAMS.md` 有记录，可回滚。

**S5 技能工坊（成长，预估 +8～12 KB）**
- 触发：一次成功且步骤 ≥4 的任务结束（或用户 `/learn`）。
- 生成草稿：`name`、`when`（何时用）、`steps`、`pitfalls`、`verify`；先落 `skills/_draft/<name>.md`。
- 用户确认 → 转正 `skills/<name>/SKILL.md`，进 `EXT` 技能库，`/` 可搜；未确认 7 天自动清理。
- 版本：每次修改留历史，可回滚（对齐 OpenClaw Skills Workshop）。
- 验收：完成一次 Steam 合集抓取 → 提议技能 → 确认 → 下次任务 `skill` 能取到并复用。

**S6 主动性与定时（预估 +8～12 KB，宿主 +200 行）**
- `cron` 存储：`{id, when(每日/每周/间隔), prompt, enabled, lastRun, nextRun}`；宿主定时器唤起页面（或页面内定时，窗口关闭则不跑——需明确）。
- 心跳：启动时生成「上次聊到哪 / 今天待办 / 未完成承诺」三行摘要，首页顶部卡片。
- 通知：托盘气泡（宿主已有 tray）；点击回到对应会话。
- 默认：**全部关闭**，用户逐条开启；每条任务显示「下次运行时间」。
- 验收：设「每天 9 点简报」→ 到点通知 + 生成；关闭后不再触发。

**S7 本地能力与浏览器（复用 A1-A9 / W1，额外 +4 KB）**
- 读：默认允许用户选的「资料目录」（桌面/文档/下载，可多选，只读）。
- 写：只允许显式授权目录；每次写确认（可记忆「此目录本会话允许」）。
- 执行：复用 Agent 的 `cmd` 白名单 + Python 运行时。
- 浏览器：复用 W1，但默认用**独立 agent profile**；需要登录态时用户手动点「用我的登录态打开」。
- 验收：读桌面文件总结；写文件需确认；越界被拒并说明原因。

**S8 记忆 UI / 隐私（预估 +8～12 KB）**
- 设置 → Soul：四个页签（用户模型 / 长期记忆 / 日记 / 技能），支持搜索、编辑、删除、暂停注入。
- 「记忆时间线」：按天看发生了什么、写了什么。
- 一键导出 Markdown 包（`USER.md` + `MEMORY.md` + `memory/*` + `skills/*` + `manifest.json`）；导入合并（冲突逐条确认）。
- 隐私：所有记忆本地；不写遥测；导出默认不含密钥；清空需二次确认 + 可选导出备份。
- 验收：导出包内容与 UI 一致；清空后不再召回；重新导入恢复。

### 5.5 数据模型（DB v4）

新增/修改 store：
- `mem`（v2）：`{id, layer:'user'|'memory'|'daily'|'skill', path, text, hash, ts, source:'user'|'tool'|'web', confidence, supersedes, tags[]}`
- `plan`：`{sid, steps[], updated}`
- `checkpoints`：`{key, sid, ws, path, versions:[{t, bytes, content|diff}]}`
- `cron`：`{id, when, prompt, enabled, lastRun, nextRun}`
- `docs`：Chat 画布文档
- `sessions` 增 `mode:'soul'`、`memoryPaused`

迁移：v3 → v4 幂等；旧 `memory`/`tasks` 数据搬进 `mem`/`plan`；导出格式升 v4，导入兼容 v3。

### 5.6 四模式关系（给用户的引导）

| 你说的话 | 该用 |
|---|---|
| 「帮我看看这段代码 / 解释一下」 | Chat |
| 「做一份 PPT / 抓这个榜单 / 跑个脚本」 | Work |
| 「改这个仓库 / 修 bug / 加功能」 | Agent |
| 「记住…」「我最近…」「帮我盯着…」 | Soul |

`MODE.route` 增加 Soul 的触发词（记住/以后/每次/提醒/我的习惯/上次说），但**默认不自动切**——涉及长期记忆的写入必须用户显式确认，避免误记。

### 5.7 验收用例（Soul）

1. 写入：说「记住我周三晚上打球」→ `USER.md` 或 `MEMORY.md` 出现条目（带日期/来源），设置页可见可删。
2. 召回：新会话问「我周三晚上有什么安排」→ 命中，回答正确，显示来源。
3. 冲突：深色 → 浅色，旧条目被替代，不并存。
4. 敏感：API key 拒写。
5. 巩固：3 天日记 → `/dream` → `MEMORY.md` 更新 + `DREAMS.md` 记录 + 可回滚。
6. 技能：完成抓取任务 → 技能草稿 → 确认 → 下次复用。
7. 主动：每日 9 点简报，到点通知；关闭后不触发。
8. 本地：读桌面文件；写需确认；越界拒绝。
9. 浏览器：登录一次后复用登录态读页面。
10. 迁移：导出 → 清空 → 导入 → 记忆恢复。

### 5.8 边界与不做

- **不做多通道**（微信/Telegram/Slack）：需要常驻网关与账号体系，超出单 exe 定位；后续可用 MCP/HTTP 桥接。
- **不做云同步/账号**：本地优先。
- **不做全自动人格演化**：人格/语气变更必须用户确认。
- **不做无审计的后台写入**：每次记忆写入都有 diff 与来源。
- **不是 OS 级隔离**：文件/命令权限是应用层白名单，不是安全沙箱。

## 6. 架构前置：`src/` 拆分与内联构建

### 6.1 先纠正一个误解

拆 `src/` **不会**减小 `index.html`（产物仍是单文件，字节不变）。它解决的是**可维护性**：现在 921 KB 的单个 `<script>` 里改一处要找半天，opencode 每次都要读 17K 行。

**体积问题必须单独解决**（D1）：要么抬上限，要么砍功能，要么把可选能力做成磁盘扩展包。

### 6.2 目标结构

```

├── index.head.html        # <head> + CSP + 主题引导
├── css/
│   ├── 00-tokens.css      # 变量、暗色
│   ├── 10-base.css
│   ├── 20-chat.css
│   ├── 30-panels.css
│   └── 40-settings.css
├── svg/symbols.svg        # 43 个 <symbol>
├── js/
│   ├── 00-boot.js
│   ├── 10-util.js
│   ├── 20-db.js
│   ├── 30-net.js
│   ├── 40-md.js
│   ├── 50-runner.js
│   ├── 60-ui.js
│   ├── 70-fs.js
│   ├── 80-work.js
│   ├── 90-sub.js

│   └── 99-app.js
├── data/providers.json   # 供应商目录

```

### 6.3 `tools/build.mjs` 规格

- 零依赖 Node；按固定顺序拼接；`<script>` 仍包在 IIFE 内（不改变执行语义）。
- 输出 `index.html`；`--check` 模式：重新构建到内存，与磁盘比对，不一致退出码 1。
- 保留 `APP_VER` 唯一来源（`src/js/00-boot.js`）。
- `tools/verify.mjs` 增加第 7 项：`build --check` 通过（防止改 src 忘构建）。
- 构建确定性：无时间戳、无随机、LF 换行（当前文件是 CRLF，需统一后再比对，避免全文件 diff）。

### 6.4 迁移步骤（一次做完，不改逻辑）

1. 冻结功能，提交/回滚脏工作区。
2. `tools/extract.mjs`：按标记把 CSS/SVG/JS 切到 `src/`，生成 `index.html` 供比对。
3. `build.mjs` 重建 → 与旧文件**逐字节一致**（除换行）；不一致就修切分，不改逻辑。
4. `verify.mjs` 7/7；真实浏览器冒烟（首页、发消息、设置五页、Work/Agent 面板）。
5. 提交 `refactor(build): src 拆分 + 内联构建（v0.4.4）`。
6. 之后所有改动只在 `src/`，`index.html` 视为产物。

## 附录 C：术语

- **图片流**：生成图片过程中按 `partial_images` 逐帧返回，前端渐进显示，而不是等最终图。
- **基架（harness）**：模型之外的工具循环、提示词、权限、上下文管理；Arena 的 HarnessTax 研究表明同一模型换基架性能差异显著。
- **bash recovery**：命令失败后能否读报错、修正、重跑直到成功。
- **tool hallucination**：模型声称调用了不存在/不可用的工具。
- **supersede**：新记忆替换旧记忆，保留链路而不是并存矛盾条目。
- **dreaming**：后台把日记蒸馏为长期记忆的巩固过程。
