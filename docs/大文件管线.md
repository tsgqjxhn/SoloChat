# 大文件与长文本管线

> 适用 v0.4.15+。目标：几十 MB 的 TXT / 日志 / 代码导出不必塞进上下文，也不靠 Python 才能查全文。

## 为什么之前读不到后半段

旧链路有四层截断：

| 层 | 旧行为 |
|---|---|
| 附件预览 | `TEXT_SLICE=256KB`，只把前 256KB 放进 `fileTexts` / prompt |
| 导入 VFS | 文本附件按 1MB 截断后写进 `workfs` |
| `vfs-read` | 只从开头返回 64KB，没有 offset；提示词还写着 6KB |
| Python 沙箱 | 只把 VFS 残片带进临时目录，写回也有约 200KB 上限 |

结果：19.9MB 的书，第 256KB 之后模型查不到，Plan 也没有只读搜索工具。

## 现在的分工

- **完整附件**：仍保存在 IndexedDB 的 `attachments` 表（原 `blob`），不丢正文。
- **VFS 引用**：文本附件写成 `external:true` 的记录，只保存 `attachmentId`、原始 `size` 和 4KB 预览，`content` 为空。
- **上下文预览**：`fileTexts` 仍是 256KB 预览；明确告诉模型“大文本用 vfs-stat / vfs-grep / vfs-read 分段”。
- **检索**：页面侧按需从附件 blob 解码全文，只把命中片段回给模型。

## 工具

### `vfs-stat <路径>`

查看文件大小、字符数、是否完整附件、是否二进制、预览是否截断。

### `vfs-grep <路径> <正则> [--max=N] [--before=N] [--after=N] [--page=N] [--case]`

在单个文本文件里按行全文检索：

- 默认每页 100 条，上限 200；
- 返回 `路径:行号:` 命中行，带前后各 1 行上下文；
- 大量命中用 `--page` 分页；
- 输出超过工具结果预算时，头部会写“本次显示 S 条”和下一页提示，不静默截断；
- Plan / Write / Free 都可用，不需要切 Free 或跑 Python。

### `vfs-read <路径> [--offset=N] [--limit=N]`

按字符偏移分段读取：

- 默认/单次上限受 `WORK_WEB_CHARS` 和结果预算约束（默认约 64KB 字符）；
- 结果给出总字符数、实际 offset/limit、是否到尾部，以及下一次该传的 offset；
- offset 是字符偏移，不是字节；UTF-8 优先，疑似 GBK 时自动尝试 `TextDecoder('gbk')`。

### Python

`py` 会把工作区文本（包括 `external` 完整附件）通过 `Promise.all` 读全后送进临时目录。单文件 32MB 字符、单次总量 48MB 字符；超限会明确列出“跳过（过大）”，不会静默丢文件。写回仍受 VFS 单文件 1MB 限制。

## 边界

- 旧 VFS 记录只有 `content`、没有 `attachmentId`：仍可读/搜索，但内容仍是旧截断副本；重新上传后才会写成全文引用。
- 二进制原文件只回元数据；文本搜索只针对非二进制文件。
- `TEXT_SLICE`、`VFS_FILE_MAX` 不做无脑放大：VFS 仍是 IndexedDB，大文件走附件引用，不复制正文。
- Agent 的真实工作区路径目前仍按原有 240KB 文本落盘上限；Work/Plan 的 VFS 全文检索不受它影响。

## 验收

1. 上传 >20MB 文本，确认 `vfs-stat` 显示“完整附件：有”；
2. Plan 下直接 `vfs-grep` 搜索只出现在后半段的词，必须命中并带行号；
3. `vfs-read --offset` 能读到尾部；
4. 切 Free 跑 Python，确认脚本能读到完整附件；
5. 用 UTF-8 与 GBK 各测一次，确认中文不乱码。
