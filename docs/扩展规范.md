# SoloChat 扩展规范（v1）

> 适用版本：SoloChat **v0.4.13** 及以后。  
> 目标：智能体（agent）、插件（plugin）、技能（skill）、工具（tool）、MCP、提示词（prompt）使用同一套声明式清单与配置 schema；按本规范写的配置会自动显示在「设置 → 扩展」对应卡片的齿轮里，用户填写后按 `{{key}}` 注入到实际执行代码，不需要再改源码。

---

## 1. 设计原则

1. **一份清单描述全部**：名称、版本、条目、配置字段都写在 `manifest.json`；不再为每种扩展单独发明配置页。
2. **schema 驱动 UI**：扩展只声明字段（key/type/required/secret/default…），SoloChat 负责渲染输入框、校验必填、保存值。
3. **值不写死**：执行时用 `{{key}}` 取配置；缺必填项直接拒绝执行并指出缺哪一项。
4. **密钥不落明文**：`secret: true` 或 `type: "password"` 在 exe 宿主里写入 DPAPI 保险库；浏览器模式没有保险库时才降级到本地配置，并提示风险。
5. **向后兼容**：没有 `config` 的旧扩展照常工作；没有 schema 的工具仍使用原来的内置工具参数（抓取页数、读写上限等）。
6. **可移植**：导出扩展包时只导出 schema，不导出用户填写的值；密钥永远不进入导出文件。

---

## 2. 目录结构

### 2.1 扩展包（plugin）

```text
my-extension/
├─ manifest.json          # 必需：包信息、条目列表、配置 schema
├─ agents/                # 可选
│  └─ researcher.md
├─ skills/                # 可选
│  └─ summarize.md
├─ tools/                 # 可选
│  └─ weather.json
├─ prompts/               # 可选
│  └─ rewrite.md
└─ README.md
```

- MCP 服务器目前写在 `manifest.json` 的 `mcp` 数组里（不支持单独的 mcp/ 目录）。
- 包内条目文件可以放在上述目录，由 `manifest.json` 显式引用；没有引用时按目录名自动识别。
- 工具必须是**声明式 HTTP JSON**，不允许携带可执行 JS（安全策略）。
- 单个扩展包最多 40 个条目；单文件读取上限 512 KB。

### 2.2 单条目

也可以只导入一个文件：

- 工具：`tools/weather.json`
- 技能：`skills/summarize.md`
- 智能体：`agents/researcher.md`
- 提示词：`prompts/rewrite.md`

单条目没有外层 `manifest.json` 时，使用文件自己的 `config` 或 frontmatter 里的 `config`；没有就是无配置。

## 3. manifest.json

### 3.1 最小示例

```json
{
  "schema": "solochat.ext/1",
  "name": "my-extension",
  "title": "我的扩展",
  "version": "1.0.0",
  "description": "一句话说明",
  "config": [],
  "items": [
    { "kind": "tool", "file": "tools/weather.json" },
    { "kind": "skill", "file": "skills/summarize.md" },
    { "kind": "agent", "file": "agents/researcher.md" },
    { "kind": "prompt", "file": "prompts/rewrite.md" }
  ],
  "mcp": []
}
```

### 3.2 字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `schema` | string | 否 | 建议 `solochat.ext/1`；当前不强制 |
| `name` | string | 是 | 包 ID；也是配置作用域 `pkg:<name>` |
| `title` | string | 否 | 显示名 |
| `version` | string | 否 | 版本号 |
| `description` / `desc` | string | 否 | 包说明 |
| `config` | array | 否 | **包级配置**，所有条目共享；字段默认 `scope: "package"` |
| `items` | array | 否 | 统一条目列表；每项 `{kind,file,config?}` |
| `tools` / `skills` / `agents` / `prompts` | array | 否 | 兼容旧写法；元素可用字符串或 `{file,config}` |
| `mcp` | array | 否 | MCP 服务器列表，见第 8 节 |

`items[].config` 和 `tools[]/skills[]/...` 元素里的 `config` 是**条目级 schema**；与包级 `config` 合并后显示在同一张卡片。

### 3.3 条目引用

```json
{
  "items": [
    {
      "kind": "tool",
      "file": "tools/weather.json",
      "config": [
        { "key": "city", "label": "默认城市", "type": "text", "default": "上海" }
      ]
    }
  ]
}
```

`kind` 取值：`tool` / `skill` / `agent` / `prompt`。MCP 走单独的 `mcp` 数组。

## 4. 配置字段 schema

### 4.1 字段定义

```json
{
  "key": "baseURL",
  "label": "服务地址",
  "type": "url",
  "required": true,
  "secret": false,
  "scope": "package",
  "default": "https://api.example.com/v1",
  "placeholder": "https://…",
  "hint": "末尾不要带 /chat/completions",
  "min": 0,
  "max": 100,
  "step": 1,
  "options": [
    { "value": "fast", "label": "快速" },
    { "value": "deep", "label": "深度" }
  ]
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `key` | string | **必填**；`[A-Za-z][A-Za-z0-9_.-]{0,63}`；执行时用 `{{key}}` |
| `label` | string | 显示标签 |
| `type` | string | `text` / `password` / `url` / `model` / `number` / `select` / `boolean` / `textarea`；默认 `text` |
| `required` | boolean | 必填；缺失时卡片提示，工具调用/探测会被拒绝 |
| `secret` | boolean | true 时按密钥处理；`password` 自动视为 secret |
| `scope` | string | `item`（默认）或 `package`；包级配置建议写 `package` |
| `default` | any | 默认值；用户没填时使用 |
| `placeholder` | string | 输入框占位文字 |
| `hint` | string | 字段下方说明 |
| `options` | array | `select` 的选项，元素可为字符串或 `{value,label}` |
| `min` / `max` / `step` | number | `number` 输入约束 |

### 4.2 作用域与保存位置

配置值保存在 `cfg.extCfg`：

```text
pkg:<包名>                  包级配置（所有条目可读）
item:<kind>:<name>          条目级配置（如 item:tool:weather）
```

- `scope: "package"` 的字段写在 `pkg:<包名>`；即使从条目卡片编辑，也写入包作用域。
- 条目字段优先读自己的 `item:<kind>:<name>`，没有再回退到 `pkg:<包名>`。
- 没有包名的单条目工具/技能，包字段没有可写作用域，按条目作用域保存。
- `secret: true` 的字段在 exe 宿主中写入保险库键 `ext:<作用域>:<key>`；`cfg.extCfg` 只保留空值，不存明文。浏览器模式没有保险库时才写入 `cfg.extCfg`。

### 4.3 保留键（建议）

以下 key 是运行时约定的常用名，扩展可以直接使用，也可以自定义：

| key | 用途 | 示例 |
|---|---|---|
| `baseURL` | 服务根地址 | `https://api.deepseek.com/v1` |
| `apiKey` | 服务密钥（secret） | `sk-…` |
| `modelId` | 模型 ID | `deepseek-chat` |
| `searchRounds` | 搜索/工具轮数 | `3` |
| `timeout` | 单次请求超时（秒） | `30` |

`apiKey` 必须写 `type:"password"` 或 `secret:true`；否则会按普通值保存。

## 5. 工具（tool）

工具是**声明式 HTTP 请求**，不执行任意 JS。文件 `tools/<name>.json`：

```json
{
  "kind": "tool",
  "name": "weather",
  "title": "天气查询",
  "desc": "查询城市天气",
  "type": "http",
  "method": "GET",
  "url": "{{baseURL}}/weather?city={arg}&key={{apiKey}}",
  "headers": {
    "Authorization": "Bearer {{apiKey}}",
    "X-Model": "{{modelId}}"
  },
  "modes": ["work", "agent"],
  "config": [
    { "key": "baseURL", "label": "天气服务地址", "type": "url", "scope": "package", "required": true, "default": "https://api.example.com" },
    { "key": "apiKey", "label": "API Key", "type": "password", "required": true, "secret": true },
    { "key": "modelId", "label": "模型", "type": "model", "default": "weather-v1" },
    { "key": "searchRounds", "label": "搜索轮数", "type": "number", "default": 3, "min": 1, "max": 10 }
  ]
}
```

### 5.1 占位符

执行时按顺序替换：

1. `{{key}}` → 该工具作用域里的配置值；
2. `{arg}` → 模型调用时传入的参数，URL 编码后填入。

示例：`url` 里的 `{{baseURL}}`、`{{apiKey}}`、`{{modelId}}` 都会先替换，再替换 `{arg}`。

### 5.2 必填校验

- `required: true` 且没有值（也没有默认值）时，`runTool` 直接拒绝：
  `「weather」缺少必填配置：API Key（扩展 → 工具 → 齿轮）`。
- 不会发出请求，不会把未替换的 `{{…}}` 发到远端。

### 5.3 卡片 UI

- 「扩展 → 工具」每张工具卡片右侧有齿轮；点击在卡片下方内联展开字段。
- 包级字段在每个条目卡片都会显示；编辑的是同一个包作用域。
- 没有 `config` 的内置工具继续显示原来的工具参数（抓取页数、读写上限等）。

---

## 6. 技能（skill）

技能 = 一段按需加载的说明。`skills/<name>.md`：

```markdown
---
name: summarize
title: 摘要
desc: 把长文压缩成要点
modes: [work, agent]
config: [{"key":"maxPoints","label":"要点数","type":"number","default":5}]
---

请把下面内容压缩成 {{maxPoints}} 条要点：
```

- 正文里的 `{{key}}` 在 `skill` 取全文时替换。
- `config` 也可以写在 `manifest.items[].config`，与 frontmatter 二选一；manifest 优先。
- 没有配置的技能不显示齿轮；有配置时在卡片右侧显示齿轮，并在内联面板填写。

---

## 7. 智能体（agent）

`agents/<name>.md`：

```markdown
---
name: researcher
title: 研究员
desc: 先查证再给结论
tools: [web, search]
modes: [work, agent]
model: "{{modelId}}"
maxTurns: 4
config: [{"key":"modelId","label":"研究模型","type":"model","default":"deepseek-chat"},{"key":"baseURL","label":"服务地址","type":"url"},{"key":"apiKey","label":"API Key","type":"password","secret":true}]
---

你是研究员。先用工具查证，再输出带来源的结论。
当前服务：{{baseURL}}
```

- 正文在子智能体启动时替换 `{{key}}`。
- `model` 支持 `{{modelId}}`；`maxTurns` 支持 `{{searchRounds}}` 之类的数字占位符（解析成整数）。
- `baseURL` / `apiKey` / `model` 会被读取并用于该子智能体的请求：填了就用扩展配置，没填回退到应用当前连接与模型；密钥走保险库。
- 自定义智能体的配置通过 `manifest.items[].config` 或 frontmatter `config` 声明；内置角色没有配置，不显示齿轮。

---

## 8. MCP

MCP 服务器可以直接写在 `manifest.json`：

```json
{
  "name": "my-mcp",
  "version": "1.0.0",
  "config": [
    { "key": "mcpToken", "label": "访问令牌", "type": "password", "secret": true, "required": true }
  ],
  "mcp": [
    {
      "name": "filesystem",
      "url": "{{mcpBase}}/mcp",
      "headers": { "Authorization": "Bearer {{mcpToken}}" },
      "config": [
        { "key": "mcpBase", "label": "MCP 地址", "type": "url", "scope": "package", "required": true, "default": "http://127.0.0.1:8931" }
      ]
    }
  ]
}
```

- MCP 卡片的齿轮显示 `config` 字段；`探测` 前检查必填项。
- `探测` 使用替换后的 URL 和 headers。
- MCP 的 `configSchema` 保存在 `cfg.mcp[]`；包级字段作用域为 `pkg:<包名>`。

---

## 9. 提示词（prompt）

`prompts/<name>.md`：

```markdown
---
name: rewrite
config: [{"key":"tone","label":"语气","type":"select","default":"专业","options":["专业","轻松","正式"]}]
---

把下面内容改写为{{tone}}语气，保留事实：
```

- `/提示词名` 插入输入框时替换 `{{key}}`。
- 勾选提示词进入本轮上下文时同样替换。
- 没有 `config` 的提示词不显示齿轮，保持原有行为。

---

## 10. 插件（plugin）

插件就是包含多个条目的扩展包：

- 包级 `config` 由所有条目共享，作用域 `pkg:<包名>`。
- 「扩展 → 插件」包卡片右侧显示齿轮（仅当包有 `config` 时），展开后编辑包级字段。
- 包内条目卡片的齿轮会同时显示包级字段和条目字段；包级字段修改后所有条目立即生效。
- 插件包不导出用户填写的值，只导出 schema。

---

## 11. 运行时替换矩阵

| 形式 | 显示配置 | 执行时替换 |
|---|---|---|
| 工具 | 工具卡片齿轮 | `url` / `headers` / `body` 的 `{{key}}`；必填校验 |
| 技能 | 技能卡片齿轮 | `skill` 取全文时替换正文 |
| 智能体 | 智能体卡片齿轮 | 正文 `{{key}}`；`model` / `maxTurns` 占位符 |
| MCP | MCP 卡片齿轮 | 探测 URL 与 headers |
| 提示词 | 提示词卡片齿轮 | `/插入` 和本轮上下文注入时替换正文 |
| 插件 | 包卡片齿轮 | 包级值供所有条目读取；不直接执行 |

## 12. 导入、导出与兼容

### 12.1 导入

- 读取 `manifest.json`（也接受 `package.json` / `ext.json`）。
- 包级 `config` + 条目 `config` 合并后写入条目的 `configSchema`。
- 条目文件里的 `config`（JSON 工具）或 frontmatter 的 `config`（JSON 字符串）也会被读取；manifest 中的条目配置优先。
- 导入失败只跳过该条目，不影响整包其他条目。

### 12.2 导出

- 工具 JSON 写入 `config` 数组。
- 技能/智能体/提示词 frontmatter 写入 `config: [JSON]`。
- 只写 schema，不写用户填写的值，不写密钥。
- 重新导入时保留同样的字段定义。

### 12.3 旧扩展

没有 `config` 的旧技能/智能体/提示词/工具照常工作；旧工具仍然使用原有内置参数页签。新增 schema 不需要迁移旧数据。

## 13. 安全规则

1. `apiKey`、`token`、`secret`、`password` 一律声明 `type:"password"` 或 `secret:true`。
2. exe 宿主：secret 写入 DPAPI 保险库，`localStorage` 只保留空值；`Vault.hydrate()` 启动时回读。
3. 浏览器模式：没有保险库，secret 会落到本地配置并明文显示风险；正式使用请用 exe 宿主。
4. 导出、配对同步、诊断包不得包含 secret 值；只允许出现 key 名称。
5. 工具 URL/headers 中不要把密钥写死；用 `{{apiKey}}`，避免扩展包泄露。
6. 必填配置缺失时工具不执行；禁止用空 `{{key}}` 发起请求。

---

## 14. 最小检查清单

发布一个扩展包前逐项确认：

- [ ] `manifest.json` 有唯一 `name`、`version`。
- [ ] 每个 `items[]` 的 `file` 存在且扩展名正确。
- [ ] 工具是声明式 HTTP JSON，没有可执行 JS。
- [ ] 所有需要用户填的字段都有 `key` / `label` / `type`。
- [ ] 密钥字段写 `type:"password"` 或 `secret:true`。
- [ ] 必填字段有 `required:true`，并尽量给 `default`/`hint`。
- [ ] 工具 URL/headers/body 里的占位符与 schema key 完全一致。
- [ ] 技能/智能体/提示词正文里的 `{{key}}` 能从 schema 取到。
- [ ] 导入后卡片齿轮能展开字段；填好后执行/探测能拿到值。
- [ ] 导出再导入后 schema 还在，值没有泄露。

## 15. 完整示例：一个带配置的工具包

```json
{
  "schema": "solochat.ext/1",
  "name": "weather-kit",
  "title": "天气工具包",
  "version": "1.0.0",
  "config": [
    {
      "key": "baseURL",
      "label": "天气服务地址",
      "type": "url",
      "scope": "package",
      "required": true,
      "default": "https://api.example.com/v1",
      "hint": "不要带 /weather"
    },
    {
      "key": "apiKey",
      "label": "API Key",
      "type": "password",
      "secret": true,
      "required": true
    }
  ],
  "items": [
    {
      "kind": "tool",
      "file": "tools/current.json",
      "config": [
        { "key": "modelId", "label": "模型", "type": "model", "default": "weather-v1" },
        { "key": "searchRounds", "label": "最多重试轮数", "type": "number", "default": 3, "min": 1, "max": 10 }
      ]
    },
    {
      "kind": "skill",
      "file": "skills/format.md",
      "config": [
        { "key": "unit", "label": "温度单位", "type": "select", "default": "celsius", "options": [
          { "value": "celsius", "label": "摄氏度" },
          { "value": "fahrenheit", "label": "华氏度" }
        ]}
      ]
    }
  ]
}
```

`tools/current.json`：

```json
{
  "name": "current",
  "title": "当前天气",
  "type": "http",
  "method": "GET",
  "url": "{{baseURL}}/weather/current?city={arg}&model={{modelId}}&retries={{searchRounds}}",
  "headers": { "Authorization": "Bearer {{apiKey}}" },
  "modes": ["work", "agent"]
}
```

`skills/format.md`：

```markdown
---
name: format
title: 天气格式
config: [{"key":"unit","label":"温度单位","type":"select","default":"celsius","options":["celsius","fahrenheit"]}]
---

把天气结果整理成中文，温度用 {{unit}} 表示。
```
