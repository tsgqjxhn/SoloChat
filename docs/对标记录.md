## #1 Agent · Claude Code

**对标点**：权限模式（permission mode）。Claude Code 把权限做成三档：plan（只读规划）、default（每次询问）、acceptEdits（自动接受编辑），而不是一个「计划门禁」布尔开关。

**我们的差距**：原来只有 `planGate` 一个开关，要么「第一次写入手动确认」，要么「全自动」，没有「只读」这一档——想让它先出方案不动文件，只能靠提示词约束，靠不住。

**改动（v0.3.6）**：
- 新增 `permMode`：`ask` / `auto` / `readonly`
- 设置 → 通用设置 → 权限模式，三选一；选 `auto` 时同步把 `planGate` 置 false，兼容旧配置
- 执行端：`readonly` 时过滤掉 `fs-write` / `cmd` / `git`，写入清空并在消息里追加「🔒 只读模式：本轮 N 处写入未执行」，读类工具照跑
- 默认仍是 `ask`，行为与之前一致

**验证**：真实宿主里三态选择存在、切 `readonly` 写入 `cfg.permMode`、切 `auto` 同时关掉 `planGate`、无 JS 报错。

**没做的**：`readonly` 的端到端没有真模型回合可跑（额度未恢复），只核对了过滤逻辑与提示注入代码路径。

## #2 Chat · Claude

**对标点**：回答的耗时可见性。Claude 网页端在回复上方显示「Thought for 3s」这类耗时，用户能一眼判断是模型慢还是网络卡。

**我们的差距**：消息头部只有时间戳、token 估算，没有任何耗时信息——排查「为什么这轮这么久」只能靠猜。

**改动（v0.3.8）**：`beginStream` 记录 `t0`，`endStream` 落库时写入 `msg.ms`，消息头部按 `m.ms` 追加一栏 `3.2s`。历史消息没有该字段则不显示，不影响旧数据。

**验证**：启动无报错；语法与渲染路径核对。没跑真模型回合（额度未恢复），耗时数字的真实性待验证。

## 下一轮待办（Work 线第一个）

**目标平台**：Claude Artifacts。

**要对标的点**：产物版本历史。Artifacts 每次改动都留版本，可在侧边切换/回看；我们现在只有写入前的快照表 `SC_SNAPS`（按相对路径存、跨会话共用一格），既不能列出历史，也没有 UI。

**已确认的前置问题**（审计中发现，未修）：`SC_SNAPS` 只按相对路径做键，跨会话/跨工作区会互相覆盖，撤销可能把 A 的旧内容写进 B 的同名文件。做版本历史前必须先把它改成 `sid + 工作区 + 路径` 三元键。

**落地顺序**：
1. 快照键改三元组（数据层，先修隔离）
2. 工作区面板每个文件加「历史」入口，列出该文件的历次写入（时间 + 字节数）
3. 单条历史可预览 diff / 一键恢复

**验收**：两个会话各自写同名 `index.html`，互不干扰；恢复任一条不会影响另一会话。

## #3 Work · Claude Artifacts（前置：快照隔离，v0.3.10）

**对标点**：Artifacts 的产物版本历史。要做历史，先得让「某次写入前的快照」能唯一归属到「某个会话 + 某个工作区 + 某个路径」，否则 A 的旧内容会覆盖 B 的同名文件。

**改动**：`SC_SNAPS` 键从 `path` 改成 `sid|ws|path`；新增 `snapKey/snapGet/snapAny`；撤销按消息所属会话的工作区读取与恢复（不再用当前显示会话的 `curWs()`），并兼容旧键。

**验证**：真实宿主启动无报错、`SC_DBG.snaps()` 可用。跨会话同名文件的隔离为代码路径核对——本轮没有真模型回合可跑。

**剩余**：历史列表 UI（每个文件的历次写入）、单条 diff/恢复。

## #3 Work · Claude Artifacts（第二步：留历史，v0.3.12）

**改动**：快照从「一个键存一份」改成「一个键存最近 5 份」，每份带时间戳与字节数；撤销与卡片按钮都取最新一条；旧格式（单字符串）自动升成数组，不丢存量数据。
