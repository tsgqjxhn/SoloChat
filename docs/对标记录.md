## #1 Agent · Claude Code

**对标点**：权限模式（permission mode）。Claude Code 把权限做成三档：plan（只读规划）、default（每次询问）、acceptEdits（自动接受编辑），而不是一个「计划门禁」布尔开关。

**我们的差距**：原来只有 `planGate` 一个开关，要么「第一次写入手动确认」，要么「全自动」，没有「只读」这一档——想让它先出方案不动文件，只能靠提示词约束，靠不住。

**改动（v0.3.6）**：
- 新增 `permMode`：`ask` / `auto` / `readonly`
- 设置 → 通用设置 → 权限模式，三选一；选 `auto` 时同步把 `planGate` 置 false，兼容旧配置
- 执行端：`readonly` 时过滤掉 `fs-write` / `cmd` / `git`，写入清空并在消息里追加「🔒 只读模式：本轮 N 处写入未执行」，读类工具照跑
- 默认仍是 `ask`，行为与之前一致

**验证**：真实宿主里三态选择存在、切 `readonly` 写入 `cfg.permMode`、切 `auto` 同时关掉 `planGate`、无 JS 报错。

**没做的**：`readonly` 的端到端没有真模型回合可跑（额度未恢复），只核对了过滤逻辑与提示注入代码路径。

## 下一轮待办（Work 线第一个）

**目标平台**：Claude Artifacts。

**要对标的点**：产物版本历史。Artifacts 每次改动都留版本，可在侧边切换/回看；我们现在只有写入前的快照表 `SC_SNAPS`（按相对路径存、跨会话共用一格），既不能列出历史，也没有 UI。

**已确认的前置问题**（审计中发现，未修）：`SC_SNAPS` 只按相对路径做键，跨会话/跨工作区会互相覆盖，撤销可能把 A 的旧内容写进 B 的同名文件。做版本历史前必须先把它改成 `sid + 工作区 + 路径` 三元键。

**落地顺序**：
1. 快照键改三元组（数据层，先修隔离）
2. 工作区面板每个文件加「历史」入口，列出该文件的历次写入（时间 + 字节数）
3. 单条历史可预览 diff / 一键恢复

**验收**：两个会话各自写同名 `index.html`，互不干扰；恢复任一条不会影响另一会话。

原来的每小时提醒会在每次触发时开一轮完整闭环（对标 → 改代码 → 构建 → 真实宿主验证 → 发版）。目标轮次预算用尽后，它还在每小时触发，但已经没有余量做完整闭环，只能空转。

**已暂停该提醒**。恢复方式：重建一个每 3600 秒的提醒，prompt 用回原文：

> 对标时间到：打开 docs/对标记录.md，看进度表里哪种模式还没满 10 个平台（优先补齐数量最少的），从候选池里挑一个本轮没对标过的国际平台，做对标 → 落到一处具体改动 → 在真实宿主验证 → 记录到文档 → 提交并发布 0.3.x 补丁版本。不要让平台重复，版本号不要到 0.4.0。

**恢复前请先确认两件事**：① 有可用模型端点（免费额度已耗尽）；② 有新轮次预算。否则仍会重复「改完只能代码核对」的老问题。

## #13 Chat · Claude（真模型验证 ask 协议）

**这次终于能用真模型验证行为类功能**：端点切到 NVIDIA integrate（`deepseek-ai/deepseek-v4.1-flash`，经本机 7897 代理）。

**验证**：Chat 模式发「帮我弄一下那个东西」，模型主动回了 `ask` 围栏并渲染成卡片（1 张卡、两个问题、8 个混在一起的选项）。**协议生效**——但它把两题的选项排成了一列。

**发现的缺陷**：`askCard` 的解析器把所有 `- ` 行都当选项，不管它们属于第几个问题；多个问题时选项会串成一列（实测 8 个）。

**改动（v0.3.49）**：选项收集在「出现非选项文本行」时停止，第二题及之后降级为说明文字。验证：3 选项 + 说明行，符合预期。

**顺带记录**：这个模型对这条 prompt 的响应约 100 秒（首字到完成），比预期慢很多，属于模型侧，不是应用问题。
