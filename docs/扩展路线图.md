# SoloChat 扩展路线图（自 v1.21 起）

> 这份文档回答三件事：① 现在「扩展」里到底有什么、边界在哪；② 21 个内置工具是否真的都能跑；③ 六类扩展各自要怎么长，先加什么后加什么。

---

## 一、现状盘点

| 标签 | 现有数量 | 来源 | 能力边界 |
|---|---|---|---|
| 智能体 | 6 个内置角色 + 自定义组合智能体（不限个数） | `SUB.ROLES` / `cfg.ext` | 内置角色只读展示，可就地开关；自定义智能体可写名字、提示词、工具白名单、轮次与 token 上限 |
| 插件 | 0 个内置 | `cfg.ext` 导入 JSON | 导入后展开成若干工具 + 技能，一次性落地，没有「包」的概念 |
| 技能 | 0 个内置 | `cfg.ext` / 插件导入 | 技能 = 一段说明文本，`skill` 工具按名取正文（限 6000 字） |
| 工具 | 21 个内置 | `BUILTIN` | 按模式分配（Chat 0 个 / Work 14 个 / Agent 12 个）；可整项关闭，关闭后模型调用直接被拒 |
| 提示词 | 用户自建（当前 1 条） | `cfg.prompts` | 只存「名字 + 正文」，输入 `/名字` 插入；右侧可看系统提示词实际拼接结果 |
| MCP | 登记即可（0 条） | `cfg.mcp` | 只能填名字 + HTTP 地址、发一次 `initialize` 探测连通性；**工具调用链路未接** |

三个需要先说清的事实：

1. **技能和插件目前是空的。** 打开「技能」「插件」两页看到「这一类还没有内容」不是 bug——它们只是承载用户导入内容的容器，产品自带内容为零。
2. **工具按模式切分。** Chat 模式 0 个工具（纯对话），Work 模式 14 个（抓取/沙箱/虚拟工作区），Agent 模式 12 个（本地读写/命令/Git）。同一个工具不会同时出现在两种模式里，除了 `web/search/get/skill/suball/agent` 这几个。
3. **自定义工具只能是声明式 HTTP。** 早期那种「一段 JS 代码」的扩展工具已经按安全策略停用，现在只认 `url` + 方法 + 请求头 + 占位符模板。

## 二、工具实现审计（21 个）

逐个核对「登记项 → 分派分支 → 实际执行者 → 结论」：

| # | 工具 | 模式 | 分派位置 | 执行者 | 结论 |
|---|---|---|---|---|---|
| 1 | `web` 抓网页正文 | work, agent | index.html:11082 | `NET.fetchPageText` | ✅ 可用 |
| 2 | `search` 联网搜索 | work, agent | 11109 | `NET.searchWeb` | ✅ 可用（需在设置里配搜索服务商与密钥） |
| 3 | `get` 抓文件落盘 | work, agent | 11162 | `NET.fileGet` + 宿主落盘，文档抽正文 | ✅ 可用（需桌面宿主） |

| 6 | `run` 沙箱运行 | work | 兜底分支（见下） | `RUNNER.runCapture` | ✅ 可用；⚠️ 分派是 fallback，未知 op 会被当 run |
| 7 | `preview` 预览产物 | work | 11233 | 打开右侧面板并加载 VFS 文件 | ✅ 可用 |
| 8 | `vfs-write` 写虚拟工作区 | work | 11126 | `WORK.vfsWrite` → IndexedDB | ✅ 可用 |
| 9 | `vfs-list` 列虚拟工作区 | work | 11153 | `DB.workfsBySid` | ✅ 可用 |
| 10 | `patch` 打补丁 | work | 11135 | `applyUnified` + `vfsWrite`（unified diff） | ✅ 可用 |
| 11 | `fs-read` 读本地文件 | agent | 9803 | `NET.fs('read')` | ✅ 可用 |
| 12 | `fs-write` 写本地文件 | agent | 写入队列 + `apply()` | `NET.fs('write')`，越界需确认 | ✅ 可用 |
| 13 | `fs-edit` 局部修改 | agent | 9781 | 唯一匹配替换后写回 | ✅ 可用（多处匹配会拒绝） |
| 14 | `fs-list` 列目录 | agent | 9808 | `NET.fs('list')` | ✅ 可用 |
| 15 | `skill` 调用技能 | work, agent | 9717 / 11030 | `EXT.skillText` | ⚠️ 功能可用，但无内置技能可调 |
| 16 | `sub` 派子智能体 | work, agent | 9754 / 11058 | `SUB.run` | ✅ 可用 |
| 17 | `suball` 并行派活 | work, agent | 9757 / 11038 | `SUB.runAll` | ✅ 可用 |
| 18 | `agent` 按角色派活 | work, agent | 9754 / 11058 | `SUB.run(role)` | ✅ 可用（6 个内置角色） |
| 19 | `cmd` 执行命令 | agent | 9729 | `NET.bridge.cmd` + 二次确认 | ✅ 可用（需绑定工作区） |
| 20 | `git` Git 操作 | agent | 9729 | 同上，命令前加 `git` | ✅ 可用 |
| 21 | 扩展工具（自定义） | 按配置 | 11070 | `EXT.runTool` → `NET.raw` | ✅ 可用（仅声明式 HTTP） |

### 审计结论

- **21 个全部有实现路径，没有登记了却没人接的空壳。**
- 三个真实缺陷，建议下个版本修掉：

| 缺陷 | 现象 | 修法 |
|---|---|---|
| `run` 是兜底分支 | 模型写了个不存在的 op（比如 ```` ```read ````），会被当成沙箱运行，报「不支持的类型」，错误信息误导 | 显式白名单：命中 `run` 才走沙箱，其余 op 一律回「未知工具 xxx，可用的是 …」 |
| MCP 说明与实现不符 | 扩展页写「可探测 `tools/list`」，代码只发了 `initialize`，没取工具清单 | 二选一：要么改文案，要么补一次 `tools/list`（推荐补，见 §3.6） |
| 技能页永远是空的 | 产品自带 0 个技能，「调用技能」这条工具链等于空转 | 内置 8 个技能（见 §3.2） |

另外两个非缺陷、但要写进文档的限制：

- `download` / `play` / `cmd` / `git` / `fs-*` 依赖桌面宿主，纯网页打开时这些工具会被拦或降级，UI 上目前只有一句 toast。
- 自定义工具不能写代码，只能声明 HTTP。想做「本地脚本工具」必须走宿主的 `cmd`。

## 三、六类扩展怎么长

原则：**先补产品自带内容（技能/提示词/插件包），再加新工具，最后打通 MCP。** 因为前者的边际成本最低、用户立刻能感知，而新工具要写宿主侧代码。

### 3.1 工具：+12（按依赖分三档）

**A 档：宿主现成能力，1～2 天一个**

| 工具 | 说明 | 实现要点 |
|---|---|---|
| `pdf` | 读 PDF 正文与简单表格 | 宿主侧 PDF 解析，分页返回，超长按页截断 |
| `ocr` | 图片/扫描件转文字 | 用 Windows 自带 WinRT OCR（`Windows.Media.Ocr`），零外部依赖、离线 |
| `img` | 把图片交给多模态模型看 | 宿主读文件 → base64 → 作为 user 消息的图片块 |
| `clip` | 读写系统剪贴板 | 宿主 `Clipboard` API，读写双向 |
| `notify` | 长任务完成弹系统通知 | 宿主托盘气泡，带会话标题 |

**B 档：要写解析或模板，3～5 天**

| 工具 | 说明 | 实现要点 |
|---|---|---|
| `http` | 通用 HTTP 请求（POST/PUT/JSON/表单，自定义头） | 复用 `NET.raw`，比声明式扩展工具多一个「临时、不落配置」的入口 |
| `csv` | 读写 CSV / TSV，带编码探测 | 纯前端解析，落 VFS |
| `zip` | 打包/解包工作区 | 宿主侧压缩库 |
| `screenshot` | 截当前窗口或整屏 | 宿主 `Graphics.CopyFromScreen` |
| `search-doc` | 跨会话 + 工作区全文检索 | 复用现有记忆的倒排索引，扩展索引范围 |

**C 档：工程量大，放后面**

| 工具 | 说明 | 为什么慢 |
|---|---|---|
| `git-pr` | 分支、推送、开 PR | 涉及凭据管理与远端写操作，要单独做权限门 |
| `code-run` | 多语言执行（python/node） | 需要宿主内置运行时或调用本机解释器，沙箱边界要重做 |
| `xlsx` | 表格读写 | 要么引库（体积），要么自己写 OOXML 子集 |

### 3.2 技能：+8 个内置（最高性价比）

技能就是一段提示词，成本极低、见效最快。建议内置并默认开启：

| 技能 | 一句话 | 适合模式 |
|---|---|---|
| `code-review` | 审查清单：边界、空值、并发、错误处理、可读性 | work, agent |
| `sql` | 写法、索引、慢查询、方言差异 | work |
| `regex` | 从自然语言到正则，附测试样例 | work, agent |
| `docx` | 生成 Word 的版式约定（标题层级、表格、页码） | work |
| `xlsx` | 生成表格的约定（表头、单位、冻结窗格、合计行） | work |
| `writing-zh` | 中文写作：去 AI 味、控制句长、少用排比 | 全部 |
| `prompt-eng` | 提示词工程：角色、约束、示例、输出格式 | 全部 |
| `unit-test` | 单测设计：等价类、边界、mock 边界 | work, agent |

配套改动：技能页现在只有开关和删除，要加「内置」徽标 + 「查看全文」抽屉（和智能体卡片一致）。

### 3.3 插件：扩展包（文件夹）✅ 已在 v1.22.0 落地

**结论先说：一个 JSON 不够。** 技能正文是长 Markdown、工具可能要带请求头模板、智能体要带工具白名单与模型参数、提示词是纯文本，把它们全塞进一个 JSON 字符串既难写也难审。所以改成「一个文件夹 = 一个扩展包」：

```
示例扩展包/
  manifest.json          ← 可选；不写就按目录结构推断
  skills/code-review.md  ← 技能：frontmatter + 正文
  tools/zen.json         ← 工具：声明式 HTTP（不能带代码）
  agents/writer.md       ← 智能体：frontmatter 写工具/模型/轮次
  prompts/weekly.md      ← 提示词：frontmatter 写名字 + 正文
```

- **导入方式**：设置 → 扩展 → 插件，「导入文件夹…」「导入文件…」，或直接把文件/文件夹拖进去。单个 `.md` 会按技能导入，单个 `.json` 按工具导入。
- **manifest.json** 只写 `name/version/skills/tools/agents/prompts` 就够；只写 `name` 也行，其余按目录补齐；写 `items` 则完全以清单为准。
- **frontmatter** 支持的键：`name / title / desc / modes / tools / model / maxTurns / maxTokens`。
- **命名冲突**自动加后缀（`code-review-2`），**单条失败**只跳过并记日志，不影响整包。
- **整包移除**：插件页每个包一张卡，点「移除整包」一次清掉它带来的所有条目。
- **导出选项**（v1.25.0）：插件页顶部「导出到」可选桌面/下载文件夹；导出后只弹提示，不再自动打开资源管理器，需要时点「打开上次导出」。文件名保留中文（`prompts/周报.md`），只清洗 Windows 非法字符。
- **系统提示词可导出**（v1.25.0）：提示词页 → 系统提示词，每段右侧「导出」把它存成一个提示词包。
- **条目详情**（v1.26.0）：技能 / 工具 / 智能体 / 提示词 / 插件每张卡都有「查看」，就地展开只读详情（正文、请求参数、声明式 JSON、包内文件树与每个文件的内容），每块可单独复制；同时只展开一个。
- **导出到桌面**（v1.23.0，v1.24.0 铺到每个分页）：每个包一张卡上「导出到桌面」，宿主把 manifest + skills/tools/agents/prompts 写进 `桌面\<包名>\`，落盘后在资源管理器里定位；提示词也会按 `prompts/*.md` 随包导出。导入↔导出构成闭环，实测 6 个文件往返后条目一致。

仓库里有一份可直接导入的 [示例扩展包](../examples/示例扩展包)（2 技能 + 1 工具 + 1 智能体 + 1 提示词）。

产品自带组合包（下一步）就在这个格式上做：有了 3.1 和 3.2 的零件，把它们打包：

| 插件 | 内容 | 场景 |
|---|---|---|
| 文档工具箱 | `pdf` `csv` `docx` 技能 `xlsx` 技能 | 读合同/报表，出 Word/Excel |
| 网络工具箱 | `http` `web` `search` `get` + `regex` 技能 | 抓数据、调接口、整理来源 |
| 数据工具箱 | `csv` `xlsx` `sql` 技能 + `search-doc` | 本地表格分析与检索 |

插件页加「内置插件」区，一键导入（导入后仍落到工具/技能两页，保持现有数据模型不变）。

### 3.4 智能体：+4 个角色 + 3 个组合

**新增内置角色**

| 角色 | 职责 | 工具白名单 |
|---|---|---|
| `researcher` | 深度检索 + 交叉求证 + 给来源 | `web` `search` `get` `fs-read` `skill` |
| `ops` | 命令、构建、部署排障 | `cmd` `git` `fs-read` `fs-write` |
| `data` | 表格/CSV 清洗与统计 | `csv` `xlsx` `fs-read` `fs-write` `run` |
| `writer` | 成稿：结构、语气、长度控制 | `fs-read` `skill` |

**新增组合智能体预设**（直接出现在「智能体」页，点一下就成一套流水线）

| 预设 | 流水线 |
|---|---|
| 全栈小队 | architect → coder → tester → review |
| 调研小队 | researcher → review |
| 文档小队 | writer → review |

组合智能体要支持「顺序依赖」：上一步的产出自动成为下一步的输入（现在的 `ORCH.pipeline` 已经有这个能力，只是还没做成预设）。

### 3.5 提示词：+15 条预设，分 5 类

现在提示词页只有用户自建。建议加「预设库」区（只读，可一键复制成自己的）：

| 类别 | 条目 |
|---|---|
| 写作 | 公众号长文、小红书笔记、周报、润色去 AI 味 |
| 代码 | 代码审查、重构方案、报错定位 |
| 学习 | 费曼讲解、考点梳理、类比解释 |
| 工作 | 会议纪要、需求拆解、邮件回复 |
| 通用 | 结构化输出、角色扮演、逐步推理 |

交互：预设卡片上带「用这条」按钮 → 复制进「用户自定义」并打开编辑器，避免污染只读预设。

### 3.6 MCP：把执行链路打通

当前只做到「登记 + initialize」。要补四件事：

1. **探测升级**：`initialize` 之后接着发 `tools/list`，把工具名、描述、入参 schema 存进 `cfg.mcp[i].tools`（现在这个字段永远是空数组）。
2. **工具映射**：MCP 工具以 `mcp__<服务器>__<工具>` 命名注入工具循环，模型能调、`EXT.isOn` 能关。
3. **调用通道**：`tools/call` 走 JSON-RPC，结果截断后回灌 `[fs-result]`；错误按现有失败重试策略处理。
4. **鉴权与超时**：每个服务器可配 `Authorization` 头与超时；失败时在卡片上标「不可用」而不是静默。

做完后，MCP 页的说明文字才配得上「外部工具服务器」这个说法。

## 四、优先级与排期

| 阶段 | 内容 | 工作量 | 用户可感知的变化 |
|---|---|---|---|
| P0 | 修 3 个审计缺陷（run 白名单、MCP 文案、技能空转） | 0.5 天 | 报错不再误导；说明不再骗人 |
| P1 | 内置 8 个技能 + 15 条提示词预设 | 2 天 | 打开扩展页就有内容可用 |
| P2 | A 档 5 个工具（pdf/ocr/img/clip/notify） | 5 天 | 能读 PDF、扫图、看图、发通知 |
| P3 | 内置插件 3 个 + 智能体 4 角色/3 组合 | 4 天 | 一键成套，不用自己拼 |
| P4 | MCP 执行链路 | 5 天 | 真能调外部工具 |
| P5 | B 档工具（http/csv/zip/screenshot/search-doc） | 10 天 | 覆盖面补齐 |

合计约 26 个工作日；P0+P1 一周内可发。

## 五、验收标准

每个阶段都要能被验证，不写「应该可以」：

- **P0**：`run` 白名单后，模型写未知 op 得到明确报错；MCP 页文案与实现一致。
- **P1**：技能页出现 8 条内置技能，`skill` 工具能取到全文；提示词页 15 条预设可一键复制。
- **P2**：给一个 PDF / 一张图 / 一段剪贴板文本，模型能通过对应工具读到内容；通知在托盘弹出。
- **P3**：导入内置插件后，工具页与技能页各多出对应条目，且能整项关闭。
- **P4**：接一个公开 MCP 服务器，能列出工具并成功调用一次（返回结果进入对话）。
- **P5**：B 档每个工具至少一个真实用例跑通。

---

## 六、明确不做

- 不做任意代码的扩展工具（安全边界不松）。
- 不做云端同步/分享（单文件本地客户端的定位）。
- 不做 MCP 的 stdio 传输（要宿主拉起子进程，另开一版再说）。
- 不内置第三方大体积库（xlsx 全功能、PDF 渲染引擎）；宁可少一个工具，不把安装包撑大。
