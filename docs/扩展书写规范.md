## 1. 一句话定位

**这份文档规定「一个扩展该写成哪一类、每类文件怎么写、字段叫什么、导入后会发生什么」**，给要往 SoloChat 里加内容的人（扩展作者、包维护者、审 PR 的人）和要核对导入行为的开发看；它不解释产品功能，也不改代码。

先说清一个最容易混的前提：**SoloChat 里「插件」这个词指两样完全不同的东西**——扩展包（文件夹）与运行时插件（Python 等）。本文 §2 末尾专门区分，§7 单独讲后者。

### 事实来源（本规范据此核对，不凭印象写）

| 事实 | 来源 |
|---|---|
| 四类文件真实格式 | `examples/示例扩展包/`（`manifest.json` / `agents/` / `skills/` / `tools/` / `prompts/`） |
| 导入行为、字段名、模式过滤、注册表 | `index.html` → `EXT` 模块：`parseFront` / `importOne` / `importGroup` / `itemEntry` / `packBuild` / `add` / `registry` / `prompt` / `toolsFor` / `skillsFor` / `runTool` / `fillTpl`（对外入口是 `EXT.importFiles`） |
| 市场清单、schema、校验、贡献指南 | `origin/Plugin` 分支：`README.md` / `index.json` / `schemas/plugin.schema.json` / `scripts/validate.mjs` / `CONTRIBUTING.md` / `CHANGELOG.md` / `plugins/*/` |
| 运行时插件目录、安装 UI | `plugins/market.json`、`index.html` 的「插件市场」UI（`BUILTIN_MARKET` / `renderMarket`） |
| 运行时插件字段与执行边界 | `host/Program.cs`：`RuntimeRoot` / `RuntimeRec` / `RunRuntimeAsync`（`list` / `install` / `remove` / `run`）、`plugins/python-3.11.9-runtime.zip` 内的 `plugin.json` |
| 静态闸门 | `tools/verify.mjs`（主分支）、`node scripts/validate.mjs`（Plugin 分支） |

## 2. 五个概念先分清

### 2.1 对比表

| 概念 | 本质 | 谁触发 | 是否执行代码 | 是否有独立上下文 | 典型用途 | 不该拿它做什么 |
|---|---|---|---|---|---|---|
| **智能体** `agent` | 一段带工具白名单、轮次/token 预算、停止条件的角色提示词（`.md`） | 母智能体经内置工具 `sub` / `agent` / `suball` 派活；或用户在「智能体」分页勾选后由调度器调度 | 自身不执行代码；但可在 `tools` 白名单内调用工具（含写盘） | **是**：独立上下文、独立轮次，只回最终结论 | 独立调研并给结论、并行跑互不依赖的子任务 | 存放长篇知识（→技能）；承载每轮都要注入的纪律（→系统提示词）；当成常驻服务 |
| **插件（扩展包）** `plugin` | **一个目录 + `manifest.json` 清单**，四类文件的分发容器 | 用户在 设置 → 扩展 → 插件 点「导入文件夹…」/「导入文件…」或拖放 | 否，不承载行为 | 否 | 把一套技能/工具/智能体/提示词打包分发、整包导出、整包移除 | 写执行逻辑；放安装脚本；当成运行时环境；在里面塞密钥 |
| **技能** `skill` | 一份**只读** Markdown 知识/清单（`.md`） | 模型用 ```skill <名字>``` 围栏取全文；`EXT.prompt` 只把「名字 + 一句话」注入系统提示词 | 否，纯文本注入 | 否，注入当前上下文 | 代码审查清单、输出格式规范、领域手册、避坑清单 | 自动执行动作；绑定工具；把长文每轮强制注入 |
| **工具** `tool` | **声明式 HTTP 模板**（`.json`），一次对外请求 | 模型用围栏 ```<名字> <参数>``` 或原生 function calling 调用，经 `EXT.runTool` → `NET.raw` | 否：不执行 JS/shell；但会发起一次网络请求 | 否 | 查天气、查 GitHub 仓库、取公开 API 数据 | 执行代码；写盘；内置密钥；跑长任务；当调度器用 |
| **提示词** `prompt` | 一段可复用指令文本（`.md`） | 用户按 `/` 从提示词分页插入，或作为系统提示词片段 | 否 | 否 | 写周报、固定输出格式、角色口吻 | 自动触发；绑定工具；当知识库/技能用 |

一句话记法：**提示词是人插的，技能是模型按需取的，工具是模型调一次的，智能体是另开一桌干完活只回结论的，插件包是把前四样装进一个盒子分发的。**

### 2.2 「运行时插件」与「扩展包插件」不是一回事

两者都叫「插件」，都在「设置 → 扩展 → 插件」区域出现，但一个是**内容包**、一个是**可执行环境**，不要互相套用字段。

| 对比项 | 扩展包插件（本文主体） | 运行时插件（Python 3.11 等） |
|---|---|---|
| 形态 | 文件夹：`manifest.json` + `skills/ tools/ agents/ prompts/` | zip：`plugin.json` + `python.exe` 等可执行文件 |
| 入口 | 「导入文件夹…」/ 拖放 / 导出到桌面 | 「插件市场」卡片「安装 / 移除」 |
| 清单 | 包内 `manifest.json`；市场侧 `index.json` | 目录 `plugins/market.json`；包内 `plugin.json` |
| 落盘位置 | 应用配置 `cfg.ext` / `cfg.prompts`（本机 IndexedDB / localStorage） | `%LOCALAPPDATA%\OpenPage\runtimes\<id>`，注册表 `runtimes.json` |
| 校验 | `node scripts/validate.mjs`（Plugin 分支） | 安装时 SHA256 校验（`RunRuntimeAsync`） |
| 是否执行代码 | **否**，工具只能是声明式 HTTP | **是**，宿主按 `entry` 起外部进程 |
| 在 `requires` 中的角色 | 声明方（待实现） | 被声明方，`id` 的来源（如 `python-3.11`） |
| 典型用途 | 分发四类扩展内容 | 让 Agent 具备 `python` 脚本执行能力 |

`EXT.registry()` 里的 `kind: 'plugin'` 只指**扩展包**：每导入一个包就生成一条 `plugin:<包名>` 记录，用于六类分页里「插件」那一页，与运行时插件无关。

## 3. 选择决策树

拿到一个需求，按下面顺序判断，**命中即停**：

```
这个需求要不要在 SoloChat 之外真跑一段代码 / 起一个进程？
├─ 要（Python、编译、批处理）──────────────► 不是扩展包能做的：装「运行时插件」（§7），
│                                            由 Agent 用 ```python``` 围栏执行
└─ 不要
   └─ 要不要对外发一次网络请求拿数据？
      ├─ 要 ───────────────────────────────► 工具（声明式 HTTP，§6.3）
      │        └─ 数据拿回来「怎么读/怎么组织」要不要另写说明？
      │           └─ 要 ───────────────────► 再配一份技能（§6.2）
      └─ 不要
         └─ 是不是「另起一桌、多轮、带工具、只回结论」的活？
            ├─ 是 ─────────────────────────► 智能体（§6.1）
            └─ 不是
               └─ 是一份需要时才读的知识/清单/规范？
                  ├─ 是 ───────────────────► 技能（§6.2，懒加载）
                  └─ 不是 → 就是一段可复用指令？
                     ├─ 是 ────────────────► 提示词（§6.4）
                     └─ 要把上面几样打包给别人？ ─► 插件包 manifest.json（§6.5）
```

补充两条硬约束：

- **需要「每次回答都生效」的纪律**（身份、证据规则、停止规则）不属于以上任何一类扩展，属于系统提示词体系（`CHAT_ID` / `WORK.protocol` / `FS.protocol`），不要靠技能或提示词去覆盖它（见 §8）。
- **需要定时/后台/常驻**的需求，当前扩展体系没有调度器：只能在会话内用「工具 + 智能体」完成，或走运行时插件由 Agent 触发。

### 容易混淆的例子

| 需求 | 该做成 | 为什么不是别的 |
|---|---|---|
| 查询天气 | **工具**（`wttr.in/{arg}?format=j1`）+ **技能**（怎么读 JSON、怎么给穿衣建议） | 要发请求 → 工具；「查完怎么组织成简报」是只读知识 → 技能；不是提示词，因为不由用户插入 |
| 写周报 | **提示词** | 用户 `/` 插入的一段可复用指令，不自动执行、不绑定工具 |
| 审查代码 | **技能** | 一份按需 `skill` 取回的只读清单；不触发动作、不发请求 |
| 独立调研并给结论 | **智能体** | 需要独立上下文、多轮、`tools` 白名单、停止条件，只回最终答复 |
| 把一套东西打包分发 | **插件包**（`manifest.json`） | 容器，本身不承载行为，别往里写逻辑 |
| 每次都要的固定输出格式 / 语气 | **提示词**（或系统提示词片段） | 不是工具（无请求）、不是技能（不该懒加载、应常驻） |
| 运行一段 Python 做数值计算 | **不是扩展包工具**：装 `python-3.11` 运行时插件，Agent 用 ```python``` 围栏 | 声明式工具不执行代码；把脚本塞进 `code` 字段会被 `scripts/validate.mjs` 拒绝 |
| 定时抓取网页并落盘 | **当前做不了** | 扩展包没有调度器；会话内只能「工具取数 + 智能体整理」，或运行时插件 + Agent |

## 4. 目录与清单规范

### 4.1 目录结构

```
<包名>/
├── manifest.json            # 清单（市场规范必填；不写则按目录结构推断）
├── skills/    *.md          # 技能：frontmatter + 正文
├── tools/     *.json        # 工具：纯 JSON，声明式 HTTP
├── agents/    *.md          # 智能体：frontmatter + 正文
└── prompts/   *.md          # 提示词：frontmatter + 正文
```

- 四个子目录名会被 `importGroup` 用来**推断类型**：`skills/ → skill`、`tools/ → tool`、`agents/ → agent`、`prompts/ → prompt`（单数 `skill/`、`tool/` 等同样识别）。
- 自动补齐时忽略 `readme.*` / `license.*` / `changelog.*`；`manifest.json` 本身不会被当成条目。
- 导入入口：`EXT.importFiles` → `importGroup` → `importOne`。清单文件名除 `manifest.json` 外，`importGroup` 也兼容 `package.json` / `ext.json`，`man.title` 可作包名——但市场规范统一用 `manifest.json` + `name`。
- 单条失败（缺 `url`、正文为空、JSON 不合法、路径不存在）只记入 `rep.skipped`，**不中断整包**；导入后要看跳过列表，别以为「没报错」就是全进去了。

### 4.2 `manifest.json` 字段表

| 字段 | 类型 | 必填 | 谁读取 / 现状 | 说明 |
|---|---|---|---|---|
| `name` | string ≤ 40 | 是 | `importGroup` | 包名，作为导入条目的「来源包」`pkg` 显示；`schemas/plugin.schema.json` 要求 `minLength:1 / maxLength:40`。示例用中文「示例扩展包」也可以，它是显示名，不是条目 id |
| `version` | string | 是 | `importGroup` → 条目 `pkgVer` | semver，见 §9；schema 约束 `^\d+\.\d+\.\d+` |
| `desc` | string | 建议 | 元数据 / 市场 | 一句话说明；`packBuild` 导出时写 `desc: 由 SoloChat 导出` |
| `author` | string | 建议 | 元数据 / 市场 | 作者；`index.json` 的市场条目必填 |
| `license` | string | 建议 | 元数据 / 市场 | 许可证，示例 `MIT`；`validate.mjs` 缺失只给 warn |
| `minApp` | string | 否 | **市场 `index.json`**（示例 `v1.28.0`） | 最低应用版本声明；**当前导入代码不读取、不强制**，见 §9 |
| `requires` | string 或 string[] | 否 | **待实现** | 运行时插件前置，见 §5 |
| `skills` | string[] 或对象数组 | 否 | `importGroup` | 相对路径清单；对象形式用 `file` / `path` 指定路径，其余键作为 `meta` 传给 `importOne` |
| `tools` | string[] 或对象数组 | 否 | `importGroup` | 同上 |
| `agents` | string[] 或对象数组 | 否 | `importGroup` | 同上 |
| `prompts` | string[] 或对象数组 | 否 | `importGroup` | 同上 |
| `items` | array | 否 | `importGroup` | **显式条目清单**：`{ file, kind, ... }`。一旦写了且非空，就完全以它为准，目录里其余文件不再自动补齐 |

> **同名不同义**：`manifest.json` 的 `items` 是**条目数组**（`{file, kind}`）；`origin/Plugin` 分支 `index.json` 每条插件里的 `items` 是**数量统计对象** `{ "tools":1, "skills":1, "agents":0, "prompts":1 }`。别把统计对象抄进 manifest。

### 4.3 文件命名与 id

| 对象 | 规则 | 依据 |
|---|---|---|
| 文件名 | ASCII kebab-case，`*.md` / `*.json`，例 `code-review.md`、`gh-releases.json` | 示例包与 Plugin 分支一致；导出时提示词文件名经 `fileSafe` 清洗 Windows 非法字符（可保留中文） |
| 条目 `name`（技能/智能体/工具） | `^[a-z][a-z0-9-]{1,24}$`：小写字母开头，2–25 字符 | `EXT.add` 强校验；`pkgName` 会把导入名归一化（小写化、非 `[a-z0-9-]` 替换为 `-`、截 22 位） |
| 中文显示名 | 放 `title` | 示例 `title: 代码审查`、`title: 成稿专家` |
| 重名 | 自动加 `-2` / `-3` 后缀 | `freeName`；`addPromptItem` 对提示词加 ` 2` |
| 提示词 `name` | 例外：`/` 面板里的可见标签，示例用中文「周报」 | `addPromptItem` 只截 40 字，不强制 ASCII；但**文件名仍建议 kebab-case** |
| `registry()` 里的 id | `kind:name`，如 `tool:zen`、`skill:code-review`、`plugin:示例扩展包` | `EXT.registry`，带类型前缀避免跨类重名 |

### 4.4 版本与模式

- **版本**：`version` 用 semver `X.Y.Z`（schema 正则 `^\d+\.\d+\.\d+`），示例 `1.0.0`；`packBuild` 导出固定写 `1.0.0`。
- **模式**只有三种：`chat` / `work` / `agent`（`S.cfg.mode`，`loadCfg` 也只接受这三个值）。
- `EXT.toolsFor(mode)` / `EXT.skillsFor(mode)` 按条目的 `modes` 数组过滤；`EXT.prompt(mode)` 只把当前模式可用的工具与技能列给模型。
- 缺省值（代码实测）：工具 `['work']`；技能 / 智能体 `['work','agent']`；提示词 `['chat','work','agent']`；`registry()` 里插件包固定 `['work','agent']`。**Chat 模式不注入子智能体清单**，但提示词可用。

## 5. 前置（`requires`）规范 —— ⚠ 待实现的新约定

> **状态：本规范已定义，代码实现待后续批次。** 当前 `index.html` 的 `importOne` / `importGroup` / `add` / `registry` / `prompt`，以及 `host/Program.cs`，都**没有**读取 `requires`；现阶段在包里写它不会报错、也不会生效、不会有 UI 提示。别对使用者承诺「写了就会自动装」。

### 5.1 要解决的问题

有些扩展内容依赖一个**运行时插件**才能用（典型：一份教模型写 Python 的技能、一个按 Python 结果整理的智能体）。需要一个统一声明，让导入时就能说清「这个条目缺什么」，而不是等模型调用时才失败。

### 5.2 约定写法

| 层级 | 位置 | 形式 | 语义 |
|---|---|---|---|
| **manifest 级** | `manifest.json` 顶层 | 字符串或数组，**推荐单个字符串** | 包内所有条目的默认前置 |
| **item 级** | frontmatter 的 `requires`，或 `manifest.json` 里 `items[]` / 各分类数组对象形式的 `requires` | 字符串或数组 | **可覆盖或追加** manifest 级声明 |

- 合法值示例：`"python-3.11"`；多个写成 `["python-3.11", "other-runtime"]`，但推荐只声明一个。
- 值必须是**已登记的运行时插件 `id`**（见 §7），与 `plugin.json` 的 `id`、`plugins/market.json` 的 `plugins[].id`、`runtimes.json` 记录里的 `id` 一致。
- 非法值：文件路径、版本号、任意描述文字、未在市场登记的 id——都视为无效。

```jsonc
// 示意（当前版本请勿写入，待实现）
{
  "name": "Python 数据分析",
  "version": "1.0.0",
  "requires": "python-3.11",
  "skills": ["skills/pandas-notes.md"],
  "items": [
    { "file": "agents/analyst.md", "kind": "agent", "requires": "python-3.11" }
  ]
}
```

### 5.3 未安装时的约定行为（待实现）

| 环节 | 约定行为 |
|---|---|
| 导入 | **条目照样可导入**，不丢弃、不报错 |
| 标记 | 条目被标记「**前置未安装**」 |
| 提示注入 | `EXT.prompt` **不注入**该条目的名字/清单 |
| 执行 | `toolsFor` / `skillsFor` 过滤掉它；工具不调用、技能不取全文、智能体不派活 |
| UI | 扩展页显示原因（缺哪个 `id`），并指向 设置 → 扩展 → 插件市场 |
| 安装 | **不自动安装**。用户手动安装对应运行时插件后，条目恢复可用 |

### 5.4 当前可核对的事实（用于判定「确实没实现」）

- `EXT.add` 落库的用户条目字段里没有 `requires`；`importOne` 只从 frontmatter 取 `kind/name/title/desc/tools/model/maxTurns/maxTokens/modes` 等键。
- `EXT.registry()` 输出的记录没有前置状态字段；六类分页（`KEY = { agent, plugin, skill, tool, prompt, mcp }`）也没有「前置未安装」徽标。
- `RunRuntimeAsync` 的 `run` 分支在运行时未安装时返回「运行时未安装：<rid>（请到 设置 → 扩展 → 插件市场安装）」——这是**调用时**的错误，不是导入时的前置标注。

## 6. 五类文件写法

四类内容文件用 **YAML frontmatter**（`---` 起止）或纯 JSON；解析器是 `parseFront`，规则如下（写之前先看，能少踩坑）：

- 键匹配 `^[A-Za-z_-]+` 且**统一小写化**：写 `maxTurns` 实际存成 `maxturns`；`importOne` 用 `m.maxturns || m.maxTurns` 兼容，但建议按模板原样写。
- 值：`true` / `false` 转布尔；`[...]` 按逗号切成数组；首尾引号会被剥掉。
- 正文取第一个 `\n---` 之后的内容——**正文里别再出现独立成行的 `---`**，否则 frontmatter 会提前结束。

### 6.1 智能体 `.md`

**字段表**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `name` | string | 是 | ASCII kebab-case id（`add` 强校验） |
| `title` | string | 建议 | 中文显示名 |
| `desc` / `description` | string | 建议 | 一句话说明 |
| `tools` | array | **是** | **工具白名单**，写成 `[web, search, skill]`；调度器按它授权，越权调用会被拦下 |
| `maxTurns` | number | 否 | 最大轮次，`importOne` 缺省 4 |
| `maxTokens` | number | 否 | token 预算，缺省 1600 |
| `model` | string | 否 | 模型 id，空串 = 跟随当前模型（`add` 存 `model`） |
| `modes` | array | 否 | 缺省 `['work','agent']` |

**正文结构**：目标 → 输入 → 步骤 → 工具使用边界 → 输出契约 → 停止条件 → 禁则。强调两点：**独立上下文**（不假设能看见母对话全文，材料要显式给）、**工具白名单**（只用 `tools` 里列的；是否可写由 `importOne` 依据白名单是否含 `fs-write` / `patch` 自动算出 `writes`）。

**最小示例**（摘自 `examples/示例扩展包/agents/writer.md` 的形态）

```markdown
---
name: writer
title: 成稿专家
desc: 把材料写成能直接发的稿子：先给结构，再给正文
tools: [fs-read, skill]
maxTurns: 3
maxTokens: 1800
model: ""
modes: [work, agent]
---
你是成稿专家「writer」。拿到材料后：
1. 先用三行说清「给谁看、要什么语气、控制在多长」。
2. 给一个提纲，让母智能体有机会纠偏。
3. 再写正文，段落短，结尾给「还可以补的三处」。
4. 停止条件：正文写完即停，不再调用工具。
禁则：你只读材料，不写文件；需要落盘时把完整内容交给母智能体。
```

**常见错误**

1. `tools` 写成字符串或漏写 → `importOne` 用 `Array.isArray(m.tools) ? m.tools : []`，结果空白名单、什么也调不了。必须写成 `[...]`。
2. 以为智能体能改文件 → 只有白名单含 `fs-write` / `patch` 才被标为可写；只读智能体正文里要明确写「不写文件」（示例即如此）。
3. 把长篇知识手册塞进正文 → 放技能，智能体正文只写流程与契约。
4. 忘写停止条件 → 子智能体可能反复调工具，`maxTurns` 缺省只有 4 轮。
5. 忘写 `modes` 又指望在 Chat 里派活 → 缺省不含 `chat`。

### 6.2 技能 `.md`

**字段表**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `name` | string | 是 | ASCII kebab-case id |
| `title` | string | 建议 | 中文显示名 |
| `desc` / `description` | string | 建议 | 一句话说明（`EXT.prompt` 注入的就是这句） |
| `modes` | array | 否 | 缺省 `['work','agent']` |

**正文结构**：何时用 → 前置（需要哪些输入/前提）→ 步骤或清单 → 输出格式 → 坑（常见错误 / 不确定处标「未验证」）。强调：**懒加载**（`EXT.prompt` 只注入「名字 + 一句话」，全文由 ```skill <名字>``` 按需取回）、**只读知识**（不执行代码、不发请求、不改文件）、**不绑定工具**。

**最小示例**（摘自 `examples/示例扩展包/skills/code-review.md` 的形态）

````markdown
---
name: code-review
title: 代码审查
desc: 审查清单：边界、空值、并发、错误处理、可读性
modes: [work, agent]
---
# 代码审查清单
何时用：用户给了一段代码要找真问题时。
前置：代码全文已给出；没给就先要，不要凭印象编。
按顺序过五类：边界 / 空值 / 并发 / 错误处理 / 可读性。
输出格式：
```
问题（按严重程度）：位置 / 现象 / 为什么是问题 / 建议改法
可以不改的：……
```
坑：不确定的地方标「未验证」，不要假装跑过。
````

**常见错误**

1. 写成「运行脚本 / 调用某工具」的动作指令 → 技能是只读文本，动作属于工具或智能体。
2. 把密钥、账号、私有接口写进正文 → 会随包导出、随上下文上传，见 §8。
3. 正文里出现独立成行的 `---` → frontmatter 被截断。
4. 忘写 `modes` 又希望在 Chat 用 → 缺省 `['work','agent']`。
5. 期望「导入后全文每轮都在」→ 实际只有名字进系统提示词，必须经 `skill` 围栏取全文。

### 6.3 工具 `.json`

**字段表**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `name` | string | 是 | ASCII kebab-case id |
| `title` | string | 建议 | 中文显示名 |
| `desc` | string | 建议 | 一句话说明，会进 `EXT.prompt` 的工具清单 |
| `type` | string | 是 | **只能是 `"http"`**；`importOne` 不强校验，但 `scripts/validate.mjs` 对非 http 报错，缺省按 http 处理 |
| `method` | string | 否 | `GET` / `POST` / `PUT` / `PATCH` / `DELETE` / `HEAD`，缺省 `GET` |
| `url` | string | **是** | 声明式地址，含 `{arg}` 占位；缺 `url` 会被 `importOne` 拒绝 |
| `headers` | object | 否 | 请求头模板，值里的 `{arg}` 同样替换 |
| `body` | string | 否 | **请求体模板**，仅非 GET/HEAD 时发送；`{arg}` 同样替换 |
| `modes` | array | 否 | 缺省 `['work']` |
| `timeout` | number | — | **不生效**：`EXT.runTool` 的 `NET.raw` 固定 `timeout: 25000`；别写无效字段 |

**`{arg}` 占位规则与约定**

- `fillTpl` 把 `url` / `headers` 值 / `body` 里**每一处** `{arg}` 替换为 `encodeURIComponent(参数)`。也就是 `/` → `%2F`、空格 → `%20`、`&` → `%26`。
- 因此：不要自己先编码；不要指望 `{arg}` 注入原始路径分隔符（例 `https://api.github.com/repos/{arg}/releases` 里传 `owner/repo` 会得到 `owner%2Frepo`）；一个工具只有一个 `arg`。
- 调用写法：```<名字> <参数>```；返回形态 `[<名字>] HTTP <状态码>\n<响应文本>`，响应超 4000 字会截断。
- 所有请求走 `NET.raw`（代理 / 超时 / CSP 由它统一管），25 秒超时。**只允许声明式 HTTP**：不得放 `code` / `js` / `script` 字段，`EXT.add` 对无 `url` 的工具直接抛错，`EXT.runTool` 对旧式 JS 工具明确拒绝执行并给迁移提示。
- **错误与超时**：网络失败、非 2xx、超时都由 `NET.raw` 回注给模型（不静默丢弃）；工具作者要在 `desc` 里写清返回结构与依赖的服务，不要假设调用方知道。

**最小示例**（摘自 `examples/示例扩展包/tools/zen.json`）

```json
{
  "name": "zen",
  "title": "随机格言",
  "desc": "调用 GitHub Zen API，返回一句编程格言",
  "type": "http",
  "method": "GET",
  "url": "https://api.github.com/zen",
  "modes": ["work", "agent"]
}
```

**常见错误**

1. 带 `code` / `js` / `script` 字段或 `type: "js"` → `scripts/validate.mjs` 报错、`EXT.add` 拒绝。
2. 用 `http://` → 校验给 warn，一律用 `https://`。
3. 把 API Key 写进 `headers` / `url` → 市场禁止、导出即泄露，见 §8。
4. 用 frontmatter 写工具 → 工具是**纯 JSON**，`JSON.parse` 会失败，该条被跳过。
5. 写 `timeout` 以为生效、或自定义 `{city}` 占位 → 都无效，只有 `{arg}`。
6. `body` 用在 GET 上 → GET/HEAD 不发请求体。

### 6.4 提示词 `.md`

**字段表**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `name` | string | 是 | `/` 面板里的可见标签；示例用中文「周报」 |
| `desc` | string | 建议 | 一句话说明（`registry()` 会取正文前 50 字作兜底） |

**正文**：可复用指令本身，由用户 `/` 插入或作为系统提示词片段；**不做自动执行、不绑定工具**。`importOne` 的 prompt 分支取 frontmatter 之后的正文（或 `m.text` 兜底），存入 `cfg.prompts`；`registry()` 给提示词的 `modes` 固定为 `['chat','work','agent']`，三种模式都能插入。

**最小示例**（摘自 `examples/示例扩展包/prompts/weekly.md`）

```markdown
---
name: 周报
desc: 把一周的零散记录压成可以直接发群的周报
---
把下面这周的零散记录整理成周报，要求：
- 开头一句话说清这周的主线，不要「本周工作总结」这种标题话。
- 正文三段：做完了什么（带结果）、卡在哪（带原因）、下周要做什么（带时间点）。
- 没提到的部分不要编，写「未涉及」。

原始记录：
```

**常见错误**

1. 希望导入后自动触发 / 绑定工具 → 提示词只由用户插入，不自动执行。
2. frontmatter 里写 `title` / `modes` / `tools` → 当前 prompt 分支只读 `name`（和 `text` 兜底），`promptEntry` 导出也只写 `name`；写了不生效。
3. 把长篇知识库塞进提示词 → 用技能（懒加载）。
4. 名字重复 → `addPromptItem` 自动加 ` 2` 后缀，别指望覆盖同名条目。
5. 正文里写「忽略上面的系统提示」→ 红线，见 §8。

### 6.5 插件包 `manifest.json`

**定位**：**分发容器，不承载行为**。它只列「这个包有哪些文件、分别是什么类型」，以及包名/版本/作者/许可等元数据；四类内容文件才承载行为。

**字段表**：见 §4.2。最小骨架：

```json
{
  "name": "示例扩展包",
  "version": "1.0.0",
  "desc": "演示扩展包的目录结构与四类文件",
  "author": "SoloChat",
  "license": "MIT",
  "skills": ["skills/code-review.md", "skills/regex.md"],
  "tools": ["tools/zen.json"],
  "agents": ["agents/writer.md"],
  "prompts": ["prompts/weekly.md"]
}
```

**与运行时插件的边界**：见 §2.2。这里再强调三条：

- 扩展包里**不放** `plugin.json`（那是运行时插件包内清单），也不放 `.exe` / `.py` 可执行体。
- `manifest.json` 不是程序入口：不要写「安装时执行」「自动运行」之类的逻辑字段。
- 导入后，`EXT.registry()` 为每个包生成一条 `kind:'plugin'` 记录（「插件」分页），包的四类条目则分别落到各自分页；`EXT.delPkg` 支持整包移除。

**常见错误**

1. 把行为逻辑 / 脚本路径写进 manifest → 它是清单，不是执行体。
2. 把 `items` 抄成 `index.json` 的统计对象 → manifest 的 `items` 是条目数组；一旦写了非空 `items`，目录其余文件不再自动补齐。
3. 清单列了不存在的文件 → 该条进 `rep.skipped`，整包「看起来成功」但少东西。
4. 用 `package.json` / `ext.json` 顶替 `manifest.json` → 代码能认，但市场校验（`scripts/validate.mjs` 找 `manifest.json`）与市场规范不认。
5. 漏 `version` → schema 必填、`importGroup` 会写入空的 `pkgVer`，来源包版本显示不出来。

## 7. 运行时插件（Python 3.11）专节

这一节讲的是**会被宿主真正起进程执行**的东西，和前面四类内容文件是两套体系。

### 7.1 官方环境与目录

- 官方条目：`plugins/market.json` → `plugins[0]`，`id: python-3.11`、`kind: runtime`、`version: 3.11.9`、`file: plugins/python-3.11.9-runtime.zip`、`sha256: 3ab929…`、`size: 26128140`。页面侧还有一份等价的 `BUILTIN_MARKET`，`NET.bridge` 不可用时兜底展示。
- 便携包内容：`python.exe` / `python311.dll` / `python311.zip` / `uv.exe` 等 + 包内 `plugin.json`、`README.md`、`LICENSE.txt`；`entry: "python.exe"`。
- 安装位置：`%LOCALAPPDATA%\OpenPage\runtimes\<id>`（`RuntimeRoot`）；注册表 `%LOCALAPPDATA%\OpenPage\runtimes\runtimes.json`（`RuntimeManifestPath`）。UI 明确写「**不需要管理员权限，不改 PATH**」——不改系统环境变量。
- 市场 UI（`renderMarket`）用 `NET.bridge.runtime('list')` 查已安装、给卡片打「已安装」；安装按钮只在宿主桥可用时启用（`bt.disabled = !NET.bridge.ok`）。

### 7.2 `plugin.json` 与市场目录字段（按代码核对）

包内 `plugin.json`（zip 内实际内容）字段：

| 字段 | 值（实例） | 说明 |
|---|---|---|
| `id` | `python-3.11` | **必填**，`RunRuntimeAsync` 反序列化成 `RuntimeRec` 后校验非空；`requires` 对应的就是它 |
| `kind` | `runtime` | 市场卡片据此显示「运行时」 |
| `name` | `Python 3.11` | 显示名 |
| `version` | `3.11.9` | 运行时版本 |
| `entry` | `python.exe` | 可执行入口；缺省时宿主补 `python.exe` 并检查文件存在 |
| `description` | 便携式 Python 3.11.9…… | 说明文字（**键名是 `description`，不是 `desc`**） |
| `license` | PSF License / uv MIT… | 许可证 |

同一个「插件」在另外两处还有字段，**别混进 `plugin.json`**：

| 字段 | 出处 | 说明 |
|---|---|---|
| `sha256` | **`plugins/market.json`**（不在 `plugin.json` 里） | 安装时由页面放进 `runtime('install', { sha256 })` 请求，`RunRuntimeAsync` 用 `Sha256File(zip)` 比对，不符抛「SHA256 校验失败」 |
| `file` / `url` | `plugins/market.json` | 本地 zip 路径或下载地址；二选一 |
| `size` | `market.json` / `runtimes.json` | 字节数；安装后宿主按目录实算 |
| `path` / `installedAt` | `runtimes.json` | 宿主 `RuntimeRec` 写入的安装路径与时间戳 |

> 说明：宿主 `RuntimeRec` 的字段是 `id/name/version/entry/path/size/installedAt`；`plugin.json` 里的 `kind/description/license` 属于附加元数据，宿主不强读。`list` 操作会剔除 `entry` 文件已不存在的记录。

### 7.3 安装 / 移除 / 执行边界（`RunRuntimeAsync`）

| op | 行为要点 |
|---|---|
| `install` | `file` 路径经 `Path.GetFullPath` 后必须落在应用目录前缀内，否则抛「**插件包路径越界**」；`url` 则下载到临时目录 → SHA256 校验 → `ExtractZipSafe` 解压 → 读 `plugin.json` → 校验 `id` 与请求 `runtimeId` 一致 → 移到 `RuntimeRoot/<id>` → 校验 `entry` 存在 → 写 `runtimes.json` |
| `list` | 返回已安装记录，过滤掉入口文件缺失的项 |
| `remove` | 删除 `RuntimeRoot/<rid>` 并移出注册表 |
| `run` | 见下 |

`run` 的执行边界（安全模型的核心）：

- 未安装直接报错：「运行时未安装：<rid>（请到 设置 → 扩展 → 插件市场安装）」。
- 脚本写到 `%TEMP%\SoloChat\run_<guid>.py`，以 `-u` 无缓冲执行；`WorkingDirectory` = `FsRootFull(cwd)`，即**当前工作区根**（只是工作目录，不是安全边界），`PYTHONPATH` 指向它，`PYTHONIOENCODING=utf-8`。
- **超时**：默认 120000 ms（120 s），可由请求 `timeoutMs` 覆盖，上限 24 h；超时先 `p.Kill()`，再 `KillProcessTree(p.Id)`（`taskkill /T /F`，连脚本 fork 出的子进程一起清，管道才会闭合），返回 `code:-1, timeout:true`；异步输出读取最多等 3 s，绝不卡住宿主；`finally` 删临时脚本。
- **网络与文件边界**：分层看，别混为一谈。
  - **已做**：便携运行时（安装到 `%LOCALAPPDATA%\OpenPage\runtimes`，不写 PATH / 不改注册表）、工作目录限定（`WorkingDirectory` = `FsRootFull(cwd)`，`PYTHONPATH` 指向它）、执行前确认、120 s 超时与 `KillProcessTree` 进程树清理、临时脚本删除。
  - **未做**：真正的 OS 级沙箱——低完整性 / 受限令牌、Job Object 资源限制、网络白名单 / 断网、文件系统 ACL 都没有。宿主只设了 `WorkingDirectory` 与 `PYTHONPATH`；Python 进程不经过 `NET.raw`，因此不受应用代理 / CSP / 超时约束（约束只有宿主侧的 120 s 等待与进程树清理），仍拥有当前用户可读写的文件权限与直接联网能力。
  - **结论**：现阶段只能叫「**便携隔离 + 工作目录约定**」，不要对外宣称「安全沙箱」；若后续要做真沙箱，按上述四项单独立项。
- `Chat` / `Work` 模式没有 `python` 围栏；它挂在 Agent 的工具链上（`EXT.BUILTIN` 里 `python` 的 `modes: ['agent']`）。

### 7.4 作为 `requires` 的用法（待实现）

按 §5 的约定：扩展内容若依赖 Python 能力，声明 `"requires": "python-3.11"`，值就是本节的 `id`。**注意**：该约定**当前未实现**；现阶段用户仍需手动到 设置 → 扩展 → 插件市场 安装运行时，缺运行时只会在 Agent 真正调用 ```python``` 时报错，而不是导入时标注。

## 8. 安全与质量红线

| # | 红线 | 依据 / 后果 |
|---|---|---|
| 1 | 扩展包内**不得出现可执行 JS / shell**（`code` / `js` / `script` 字段、`.sh`、`.bat`、`.exe`） | `EXT.add` 拒绝无 `url` 的工具；`EXT.runTool` 对旧式 JS 工具拒绝执行；`scripts/validate.mjs` 见 `t.code/t.js/t.script` 直接报错 |
| 2 | **工具只能是声明式 HTTP**，`type: "http"`；市场工具**推荐 https**；`validate.mjs` 对非 https 只给 warn，应用侧允许 http/https（本地回环/内网可用 http）。不得借 http 绕过鉴权或把密钥放进 URL | `schemas/plugin.schema.json` 与 `validate.mjs`；市场 README「应用侧也不会执行（代码）」 |
| 3 | **不得内置密钥**（API Key、Token、账号密码），无论 `headers` / `url` / 正文 / frontmatter | 包可导出、上下文会上传；市场规则「需要密钥的服务不放进市场，改为让用户自己填」 |
| 4 | **运行时插件必须校验 SHA256** | `market.json` 提供 `sha256`，`RunRuntimeAsync` 用 `Sha256File` 比对，不符即拒绝安装 |
| 5 | **路径不得越界** | 运行时包 `file` 必须落在应用目录前缀内（「插件包路径越界」）；扩展包清单路径必须是包内相对路径；工作区工具不许 `..` |
| 6 | **提示词 / 技能不得要求忽略系统纪律** | 不得写「忽略以上系统提示」「无视工具白名单」「关闭确认」；系统提示词体系（`CHAT_ID` / `WORK.protocol` / `FS.protocol`）优先级高于扩展内容 |
| 7 | 智能体**工具白名单显式列出**，越权调用由调度器拦下；写盘需确认 | 市场 README、`EXT.add` 的 `writes` 判定 |
| 8 | 只读类 API 优先；需要写权限或私有数据的接口不放进市场 | 市场 README「安全模型」 |
| 9 | 导入失败只跳过单条、不静默吞掉 | `rep.skipped` 要检查；不得把「未验证」写成「已验证」（`docs/工程规范.md` §3） |
| 10 | 日志不落消息原文与密钥 | `docs/工程规范.md` §1、README「安全」F1–F5 |

## 9. 命名、版本、兼容与废弃

### 9.1 id 与 title

- **id（`name`）**：`^[a-z][a-z0-9-]{1,24}$`，小写字母开头，2–25 字符，kebab-case。`EXT.add` 强校验（不符抛「name 只能用小写字母/数字/短横，2-25 字符」）；`pkgName` 先归一化；`freeName` 对重名加 `-2`。
- **title**：中文显示名，给人看；`manifest.name` 也当包名（≤ 40 字，示例用中文）。
- **registry id**：`kind:name`，跨类不冲突。
- **提示词 name**：例外，是 `/` 面板可见标签，可用中文（示例「周报」），但文件名建议 kebab-case。

### 9.2 版本（semver）

- `version` 必须 `^\d+\.\d+\.\d+`（`schemas/plugin.schema.json`），如 `1.0.0`。
- `MAJOR` 改了字段含义/删条目、破坏导入；`MINOR` 加条目/加可选字段；`PATCH` 改正文措辞、修错。
- 导入后版本写进每个条目的 `pkgVer`，「查看」抽屉里显示「来源包 名称（版本）」。
- `packBuild` 导出固定 `1.0.0`（导出包是新包，不继承原版本号）——需要保留版本请手工改 manifest。

### 9.3 兼容与 `minApp`

- `minApp` 出现在 `origin/Plugin` 分支 `index.json` 的市场条目里（示例 `"minApp": "v1.28.0"`），语义是「最低应用版本」。
- **当前状态**：`importGroup` / `importOne` **不读取、不强制** `minApp`；`schemas/plugin.schema.json` 也没列它（`additionalProperties: true`）。它目前是**市场元数据**，供人审 PR，不是运行时门禁。写规范时按「声明、待接入」表述，别写成「低于版本会拒绝导入」。
- 真正生效的兼容约束是**字段名与 `modes`**：字段改名、模式取值超出 `chat/work/agent` 会让条目被跳过或永不可用。

### 9.4 废弃流程与 changelog

1. 先改 `origin/Plugin` 分支 `index.json`：给条目标注或移除；保留目录至少一个发布周期，不要静默删目录。
2. 在 `CHANGELOG.md` 追加一条（格式参照现有 `## 1.0.0 — 2026-11-02`）：写清废弃原因、替代包、生效版本。
3. 包内 `manifest.json` 的 `desc` 注明「已废弃」，避免用户导入后困惑。
4. 跑 `node scripts/validate.mjs` 确认移除后 `index.json` 与目录仍一致（校验会双向检查「目录没登记 / 登记没目录」）。
5. 应用侧的整包移除是 `EXT.delPkg`（按 `pkg` 清 `cfg.ext` 与 `cfg.prompts`），废弃包不会被自动清除，需用户自行移除。

## 10. 验收清单（新建一个扩展包后逐项打勾）

| # | 检查项 | 怎么验 |
|---|---|---|
| 1 | [ ] `manifest.json` 与所有 `tools/*.json` 是合法 JSON | `node -e "JSON.parse(...)"` 或编辑器；`importOne` 对不合法 JSON 会跳过该条 |
| 2 | [ ] 四类 `.md` 的 frontmatter 完整（`---` 起止、技能/智能体/提示词都有 `name`） | 对照 §6 各字段表；`validate.mjs` 检查 `fm.name` |
| 3 | [ ] manifest 里列的路径都存在、且都在包内 | `validate.mjs`；导入后看跳过列表 `rep.skipped` |
| 4 | [ ] 条目 `name` 不重复、符合 kebab-case | `freeName` 若加了 `-2` 说明撞名了；白名单/引用要用最终名字 |
| 5 | [ ] 无密钥、无 `code/js/script`、无非 http 工具、无 `http://` | `validate.mjs` + 人工过一遍 §8 |
| 6 | [ ] `requires` 合法（指向已登记的运行时插件 `id`，如 `python-3.11`） | **待实现约定**：目前写了也不生效，先按 §5 校对该值本身合法；不要对外宣称会自动安装 |
| 7 | [ ] 导入后条目出现在**正确分页**（智能体 / 插件 / 技能 / 工具 / 提示词） | `EXT.registry()` 的 `kind` 决定分页；`KEY = { agent, plugin, skill, tool, prompt, mcp }` |
| 8 | [ ] `modes` 正确：切到 `chat/work/agent` 各看一眼是否该出现 | `EXT.toolsFor` / `skillsFor` 按 `modes` 过滤 |
| 9 | [ ] 工具能调用：围栏 ```<名字> <参数>``` 发出请求并回 `[名字] HTTP …` | `EXT.runTool` → `NET.raw`；注意 `{arg}` 被 `encodeURIComponent` |
| 10 | [ ] 技能能懒加载：系统提示词里只有名字 + 一句话，```skill <名字>``` 能取回全文 | `EXT.prompt` / `EXT.skillText` |
| 11 | [ ] 智能体能派活：`tools` 白名单生效、按 `maxTurns` 收敛、只回结论 | `sub` / `agent` / `suball`；`writes` 由白名单推导 |
| 12 | [ ] 提示词能 `/` 插入 | 输入区 `/` 面板，`cfg.prompts` |
| 13 | [ ] `node scripts/validate.mjs` 通过 | **在 `origin/Plugin` 分支根目录**跑：校验 manifest、路径、声明式 HTTP、frontmatter、`index.json` 与目录一致 |
| 14 | [ ] `node tools/verify.mjs` 通过 | 主分支静态闸门（只校验 `index.html` 与 csproj 版本，不校验扩展包），确认没把仓库弄坏 |

> 注意两个脚本不是一回事：`scripts/validate.mjs` 只在 `origin/Plugin` 分支存在，管的是**扩展包内容**；`tools/verify.mjs` 在主分支，管的是**单文件 `index.html` 的体积/语法/版本**。新增扩展包不改 `index.html`，所以第 14 项应恒绿。

## 11. 反模式清单（看起来像，其实不该这么做）

| # | 反模式 | 正确做法 |
|---|---|---|
| 1 | 把一段 Python 脚本塞进工具 JSON 的 `code` 字段，指望导入后能跑 | 工具只能是声明式 HTTP；要执行代码就装 `python-3.11` 运行时插件，由 Agent 用 ```python``` 围栏跑（§7） |
| 2 | 把 API Key 写进工具 `headers` 省得用户配置 | 市场禁止内置密钥；改成让用户自己填，或干脆不放进市场（§8） |
| 3 | 用技能「每次自动跑一遍检查」 | 技能是只读懒加载知识；自动动作要用工具（请求）或智能体（多轮） |
| 4 | 给提示词绑 `tools`，希望插入后自动触发工具 | 提示词不绑定工具、不自动执行，只由用户 `/` 插入（§6.4） |
| 5 | 用智能体写一份《XX 语言避坑手册》 | 知识放技能（按需取）；智能体正文只写目标、步骤、输出契约、停止条件（§6.1） |
| 6 | 在扩展包里放 `install.sh` / `setup.js`，指望导入时执行 | 扩展包内不得有可执行 JS/shell；运行时插件走「插件市场」安装并由宿主校验 SHA256 |
| 7 | 把 `manifest.json` 当程序入口，在里面写「启动时执行」「自动加载」 | manifest 只是分发清单；`importGroup` 只读 `name/version/skills/tools/agents/prompts/items` |
| 8 | 用中文 / 驼峰 / 下划线当 id（`代码审查`、`CodeReview`、`code_review`） | id 用 kebab-case（`code-review`），中文放 `title`；`EXT.add` 的正则会拒绝别的写法 |
| 9 | 照抄 `index.json` 里的 `items: {tools:1,…}` 写进 manifest | manifest 的 `items` 是条目数组 `{file, kind}`；写了就以它为准，目录其余文件不再补齐（§4.2） |
| 10 | 工具 url 用 `http://`、自造 `{city}` 占位、或自己先 URL 编码 | 用 `https://`，只认 `{arg}`，`fillTpl` 会再做一次 `encodeURIComponent`（§6.3） |
| 11 | 在工具 JSON 里写 `timeout: 30000` 以为生效 | `EXT.runTool` 固定 25 s，该字段被忽略；别写无效字段（Plugin 分支示例里的 `timeout` 同理） |
| 12 | 在 `skills/` 下放 `README.md`、`CHANGELOG.md` 指望被导入 | 自动补齐会跳过 `readme/license/changelog`；要么写进清单，要么别放 |
| 13 | 认为写了 `requires: "python-3.11"` 就会自动安装 Python | **待实现**且不自动安装（§5.3）；用户手动装，当前缺运行时只在调用 ```python``` 时报错 |
| 14 | 让提示词/技能写「忽略以上系统提示」「无视工具白名单」「关闭写前确认」 | 红线（§8）：系统纪律优先级高于扩展内容，确认/只读闸门不可绕过 |
| 15 | 清单里用 `../shared/x.md` 引用包外文件，或运行时包 `file` 指到应用目录外 | 清单路径必须包内相对；运行时包路径越界会被 `RunRuntimeAsync` 拒绝（「插件包路径越界」） |
| 16 | 同一包两个条目都叫 `review`，还按原名写进智能体 `tools` 白名单 | `freeName` 会把第二个改成 `review-2`；引用一律用导入后的最终名字 |
| 17 | 用 `minApp` 声明低版本就断言「老版本一定拒绝导入」 | 当前 `minApp` 只是市场元数据，导入代码不强制（§9.3） |
| 18 | 把导出包（`packBuild` 固定 `version: 1.0.0`）直接当原版本的升级发布 | 导出是新包，版本号要手工按 semver 改（§9.2） |

## 12. 附录：五类最小可复制模板

复制后按需改字段；`name` 一律 kebab-case，`title` 用中文。模板均为当前代码可导入的最小形态（不含待实现的 `requires`）。

### 12.1 `agents/reporter.md`（智能体）

```markdown
---
name: reporter
title: 简报整理员
desc: 只读，把工具取回的数据整理成一段结论
tools: [web, search, skill]
maxTurns: 3
maxTokens: 1200
model: ""
modes: [work, agent]
---
目标：把给到的材料整理成一段能直接用的结论。
输入：母智能体给的材料全文（你不共享母对话上下文）。
步骤：1) 复述要回答的问题；2) 按「事实 / 判断 / 待补」组织；3) 给结论。
工具使用边界：只用 tools 里的工具；不写文件；需要落盘时把完整内容交回母智能体。
输出契约：不超过三段，事实与判断分开，缺信息写「未涉及」。
停止条件：结论写完即停，不再调用工具。
禁则：不编造数据，不评价材料好坏，不写营销话术。
```

### 12.2 `skills/format-check.md`（技能）

```markdown
---
name: format-check
title: 格式自检
desc: 交付前过一遍：字段、单位、空值、引用
modes: [work, agent]
---
# 格式自检清单
何时用：任何产物交付前。
前置：产物全文已给出；没给就先要，不要凭印象判。
步骤：
1. 字段齐全：该有的键都在，没有多余的键。
2. 单位与格式：日期、数值、编码统一。
3. 空值与边界：空数组、单元素、超长文本是否写清。
4. 引用：出现的编号/链接都能对上。
输出格式：`问题：位置 / 现象 / 改法`；无问题写「自检通过」。
坑：不确定处标「未验证」，不要假装跑过。
```

### 12.3 `tools/quote.json`（工具）

```json
{
  "name": "quote",
  "title": "随机格言",
  "desc": "GET 公开 API，返回一句文本；参数会 URL 编码后填进 {arg}",
  "type": "http",
  "method": "GET",
  "url": "https://api.example.com/quote?topic={arg}",
  "headers": { "Accept": "text/plain" },
  "modes": ["work", "agent"]
}
```

### 12.4 `prompts/standup.md`（提示词）

```markdown
---
name: 站会
desc: 把零散进展压成三行站会同步
---
把下面的进展整理成站会同步，要求：
- 三行：昨天做完什么、今天做什么、卡在哪。
- 每行不超过两行，动词开头，不写「持续跟进」这类空话。
- 没提到的写「未涉及」，不要编。

原始进展：
```

### 12.5 `manifest.json`（插件包）

```json
{
  "name": "我的扩展包",
  "version": "1.0.0",
  "desc": "一句话说明这个包解决什么",
  "author": "你的名字",
  "license": "MIT",
  "skills": ["skills/format-check.md"],
  "tools": ["tools/quote.json"],
  "agents": ["agents/reporter.md"],
  "prompts": ["prompts/standup.md"]
}
```

可选字段（按 §4.2 / §9 追加）：`minApp`（市场元数据，当前不强制）、`items`（显式条目数组，写了就以它为准）。
`requires` 见 §5——**待实现，当前版本不要写入 manifest**。
