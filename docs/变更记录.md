## v0.5.8 · 供应商配置隔离（Key 串号修复）

**根因不是偶发，是确定性路径：**

1. 设置页「供应商」下拉切换时，`applyProv` 只换 `baseURL` / 协议 / 鉴权方式，**不碰 apiKey**。从 OpenAI 切到 NVIDIA，OpenAI 的 Key 就原样留在新供应商配置里。
2. `setCfg` 会把扁平字段回写到“当前配置组”，其中包含 `apiKey`；任何在扁平层写 Key 的操作都会落到当时活跃的那一组。
3. Key 输入框没有归属标记；切换配置组后，旧面板的迟到 `change` 事件可能写进新组。

**修复：**

- 切换供应商且**域名变化** → 清空该组 Key，并提示“旧 Key 已清空，请填写该供应商的 Key”；同域名重套预设、自定义网关保留 Key。
- `setCfg` 不再把 `apiKey` 回灌配置组；演示模式加 `__flatOnly`，只改运行时，不污染供应商配置。
- Key 输入框带 `data-owner`，归属不匹配的迟到事件直接丢弃并重建面板。
- 启动（保险库回读完成后）与删除配置组时校验：Key 前缀与地址域名不符、或同一个 Key 挂在不同供应商 → 只保留归属正确的那个，其余清空并提示。
- 同厂商多套配置共用一个 Key 视为合法，不清理；无法判断归属的自定义网关保持原样。

**验证（真实浏览器，本地页面）：**

- Nvidia 组塞入 `sk-proj-…` → 重载后该组 Key 为空，OpenRouter 的 `sk-or-…` 保留。
- OpenAI 组（`sk-proj-…`）切供应商到 NVIDIA → 地址变为 NVIDIA、Key 清空、提示已清空。
- 两个不同厂商挂同一个 Key → 只保留域名匹配的，另一个清空；两个 OpenAI 组共用同一个 Key → 都保留。
- 旧面板的 Key 输入在切换后再触发 `change` → 新组 Key 不变。
- 删除 OpenAI 组 → 剩余 Nvidia 组的 `nvapi-…` 不变，扁平镜像同步。

`BUILD OK 1,167,759`、`verify 7/7`；exe **3,334,144 B**（0.5.8.0）。
