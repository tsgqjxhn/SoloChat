## v0.4.1

本轮 4 项修复（实现细节见 `docs/审计-v0.4.md`「修复进度」表）：

- **Anthropic / Gemini 思考字段**：`NET.buildBody()` 按 `protocolNow()` 分流。Anthropic 仅对支持 extended thinking 的 Claude 型号发 `thinking:{type:'enabled',budget_tokens}` 并同步抬高 `max_tokens`（至少 `budget+2048`，原本未设用 `budget+4096`）；Gemini 2.5/3 写内部字段 `thinking.budget_tokens`，由 `toGemini()` 转成 `generationConfig.thinkingConfig.thinkingBudget`（`disabled=0`、`enabled=-1`）。OpenAI chat / responses 仍走 `reasoning_effort` 等原有逻辑。
- **Azure「测试连接」跳过 /models**：`NET.testConn()` 第 1 步遇 Azure 记「Azure 无 /models，跳过」并直接进第 2 步；只有非 Azure 的 endpoint 异常才按失败返回。
- **切换供应商提示模型池未清**：`applyProv()` 在厂商变化且模型池非空时追加一条 toast，提示核对模型 ID，不自动清空模型池。
- **文案**：扩展选择器 `sub`→「派子智能体（单任务）」、`agent`→「按角色派活」；顶栏无模型选项「（无模型）」→「选择模型」。

验证方式（本轮已执行）：`node tools/verify.mjs` 6/6 PASS；`dotnet build host/SoloChatHost.csproj -c Release` 编译成功（0 error，1 条既有 CS8032 分析器 warning）；真实实例 `buildBody` 探针（Anthropic / Gemini / OpenAI 共 13 组用例）；真实实例 `testConn()` 调用（Azure 跳过第 1 步、进入第 2 步）；真实浏览器点击（供应商下拉切换与两条 toast、同厂商不重复提示）与 DOM 核对（顶栏选项、`EXT.BUILTIN` 标题）；代码核对。本轮按约束未重新 `publish`，`dist/SoloChatHost.exe` 仍是 v0.4.0 产物。
