## P0 — 配置双源漂移（必须先修）

`S.cfg` 的扁平连接字段与 `presets[activePreset]` 是两份数据；`setCfg()` 只写扁平字段，`loadCfg()` 启动时又用预置组覆盖扁平字段。

**证据 1（演示模式不持久）**

1. 干净 localStorage，点主页「试用演示模式」。
2. 立即读：`S.cfg.baseURL='mock'`、`S.cfg.currentModel='mock-demo'`，但 `presets[0].baseURL=''`、`models=[]`，顶栏模型选择器显示「（无模型）」。
3. 刷新后：`S.cfg.baseURL=''`、`currentModel=''`，演示配置丢失；localStorage 里还留着无效的扁平 `baseURL:'mock'`。

**证据 2（模型池点击不落预置）**

- `index.html` 约 12351、13529、13591 行的 `setCfg({currentModel/models})` 都只改扁平字段；`/model` 命令曾单独打补丁，说明这是重复出现的模式。
- `mirrorPreset()` 会写 9 个连接字段，但 `loadCfg()` 只从预置镜像回 4 个（baseURL / apiKey / models / currentModel），`protocol`、`provId`、`authType`、`chatPath`、`modelsPath`、`quirks` 没有镜像。

**修法**

- `setCfg(patch)`：若 patch 含连接字段（`baseURL/apiKey/models/currentModel/provId/protocol/authType/chatPath/modelsPath/quirks`），同步写进 `AP()`，保证扁平字段永远是预置的镜像；不要反向覆盖。
- `loadCfg()`：从 `act` 镜像全部连接字段；旧预置没有这些字段时回退到顶层 `c.*` 或默认值。
- 「试用演示模式」：走同一个 setCfg，并把 `protocol` 设为 `openai-chat`、`provId` 清空、`quirks` 清空。
- 检查所有 `setCfg({...currentModel...})` 调用点，删除重复的补丁逻辑。

**验收**

- 干净环境点演示 → 顶栏显示 `Mock Demo`（或 `mock-demo`），`presets[0]` 与扁平字段一致；
- 刷新后演示仍在，模型选择器仍显示 mock-demo；
- 设置里切换模型 / `/model` 命令后刷新，选择不丢；
- 切换预置组，protocol / baseURL / quirks 全部跟着切。

## P1

### 1. 原生 tools 不遵守「本轮勾选」和「扩展关闭」

**证据（本轮实测，2026-11-06）**

- `EXT` 没有 `enabled()` 方法（`toolSchemas()` 里那句判断永远为假）。
- 关闭 `fs-write`、`web` 后，`SC_DBG.net.toolSchemas()` 仍返回这两个工具。
- 本轮只勾选 `tool:fs-read` 后，schema 仍返回全部 22 个工具。
- 更底层：`EXT.setOn('fs-write', false)` 当场 `isOn` 为 false，但 `cfg.extOff` 仍是 `[]`；刷新后 `isOn` 回到 true。**「内置能力可逐个关闭」刷新即失效**。
  根因：`find(id)` 返回的是 `BUILTIN` 原始对象，没有 `kind` 字段；`isOn`/`setOn` 用 `it.kind === 'builtin'` 判断，永远不成立，于是把内置项当成用户扩展，把 `on` 写在内存对象上而不是 `cfg.extOff`。

**影响**：模型被允许调用用户已关闭/未勾选的工具；围栏路径会拒绝，但模型白跑一轮并可能编造结果。扩展页的关闭开关看起来生效、刷新后全部复活。

**修法**：先修 `isOn`/`setOn` 对内置项的判定（用 `isKnownBuiltin(id)` 直接分支，写 `cfg.extOff`）；再让 `toolSchemas()` 过滤 `e.on === false`、`EXT.isKnownBuiltin(id) && !EXT.isOn(id)`、`PICK.deny(id)`、`MODE.denied(id)`；只输出当前协议支持且当前模式可用的工具。白名单逻辑与 `FS.scan`/`WORK.scan` 共用同一套判断，避免两处漂移。

### 2. Responses 协议丢图片，且默认 `store:true`

**证据**：用 `SC_DBG.net.convertBody()` 输入含 `text + image_url(data:) + document` 的消息：

- `openai-chat`、`anthropic-messages`、`gemini` 都保留了图片；
- `openai-responses` 的 `input` 只有 `input_text` + `input_file`，**没有 `input_image`**。

另外 `toResponses()` 没有设置 `store`。OpenAI Responses API 默认会把响应存 30 天，与本项目「100% 本机、无遥测」的定位冲突。

**修法**

- 图片转 `{ type:'input_image', image_url: <data URL 或 https URL> }`，文本转 `input_text`，文档保留 `input_file`；
- 默认 `store:false`（如未来要开关，走配置，不要默认开）。

### 3. Gemini 拉不到模型列表

`parseModels(j)` 只认 OpenAI 的 `{data:[{id}]}`。Gemini `/v1beta/models` 返回 `{models:[{name:'models/gemini-...', inputTokenLimit, outputTokenLimit, ...}]}`，因此：

- 设置页「获取列表」对 Gemini 永远是空；
- `modelCaps` 也拿不到 Gemini 的上下文/输出上限。

**修法**：`parseModels` 兼容 `j.models`；`name` 去掉 `models/` 前缀；`inputTokenLimit → ctx`、`outputTokenLimit → out`；`displayName` 可用于显示。保持 OpenAI / Anthropic 分支不变。

### 4. 非流式 JSON 兜底只认 OpenAI

`fetchStream()` 在服务端忽略 `stream`、返回 `application/json` 时，直接读 `j.choices[0].message`：

```js
var msg = j.choices && j.choices[0] && j.choices[0].message || {};
if (msg.content) opt.onDelta(msg.content, false);
opt.onDone(j.usage || null);
```

Anthropic（`content[]`）、Gemini（`candidates[0].content.parts[]`）、Responses（`output[]`）在这条路径上都会得到空回复。

**修法**：改用已有的 `parseNonStream(j)`；同时把 `usage` 转给 `opt.onUsage`，把 `tool_calls` 收进 `makeToolAcc` 后交给 `onDone`。`parseNonStream` 也补上 `store:false` 无关，纯解析。

### 5. `reasoningField` 是死配置

`providers` 里给 DeepSeek / Qwen / OpenRouter 配了 `reasoningField`，设置页也能改，但解析器两处都写死：

```js
var r = d.reasoning_content != null ? d.reasoning_content : d.reasoning;
```

`reasoningField:'reasoning'` 之所以看起来能用，只是因为兜底恰好是 `reasoning`；填 `thinking` 完全不生效。

**修法**：`createParser()` 与 `flushWholeJson()` 用 `quirksNow().reasoningField` 优先，回退 `reasoning_content` / `reasoning` / `thinking`。注意 `createParser` 在 `NET` 闭包内，`quirksNow` 已在该闭包定义。

### 6. Azure 预置地址被多加 `/v1`

`normBase('https://x.openai.azure.com/openai/deployments/d')` 返回 `.../deployments/d/v1`，而 Azure 的正确路径是 `.../deployments/d/chat/completions?api-version=...`（没有 `/v1`）。

**修法**：`normBase()` 对包含 `/openai/deployments/` 或主机以 `.openai.azure.com` 结尾的地址不补 `/v1`；`endpoint()` 对 Azure 的 models 请求给出明确失败提示（Azure 没有通用的 `/models`），不要拼出错误 URL。

### 7. Python 运行时执行无超时

`host/Program.cs` 的 `RunRuntimeAsync` 用 `p.WaitForExit()` 无限等待；页面调用也没有超时。用户脚本死循环会永久占住工具链，只能杀宿主。

**修法**：请求可带 `timeoutMs`（默认 120000），超时后 kill 进程树（`taskkill /T /F /PID` 或等价实现），返回 `{timeout:true, stderr:'…'}`；脚本文件放 `finally` 删除；页面在结果里显示「超时」。
