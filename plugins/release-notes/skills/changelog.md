# 写更新日志

## 步骤

1. ```gh-releases owner/repo``` 拿最近几条 Release（含 tag、发布日期、正文）。
2. 按语义归类，不按原文字面顺序：
   - **新增**：新功能、新选项
   - **修复**：bug、崩溃、错别字级别的修正
   - **变更 / 破坏性**：行为变化、配置项改名、删除接口
3. 每条一句话，动词开头；带上 PR 号或作者（原文有就带）。
4. 破坏性变更单独成段并写清「需要用户做什么」。

## 反例（不要这样写）

- 「修复了一些问题」「优化了体验」——没有信息量。
- 照抄 commit 标题堆成列表——读者看不懂。
- 把内部重构写成用户可见变化。

## 输出

```markdown
## v1.4.0 — 2026-11-02

### 新增
- …

### 修复
- …

### 破坏性变更
- …（需要做什么）
```
